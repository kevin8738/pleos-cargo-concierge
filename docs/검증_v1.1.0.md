# v1.1.0 보완 및 검증 기록

6인 모의심사에서 반복된 제어 종료·알림 부담·재진입·검증 근거 문제를 보완했습니다. 제품 가설과 실차 효과는 코드 검사 결과와 구분합니다.

## 구현한 변경

| 지적 | 반영한 동작 | 확인 근거 |
|---|---|---|
| 원래 설정과 사용자 변경의 소유권 | 물리 속성별 원값을 읽은 뒤 요청. 현재값이 마지막 요청값과 다르면 덮어쓰지 않음. 요청 후 재조회 일치 때만 적용·복원 확인 | CabinSettingOwner 회귀 11개, Pleos 어댑터 컴파일 |
| 지연 명령·교체·실패 | 세션 세대로 오래된 대기 적용/결과 무효화. 자리·프리셋 교체는 복원 후 적용. 복원 실패 시 새 적용 보류, P 정차 후 재확인 | 명령 세대 검사, 프리셋 교체 회귀, 독립 코드 검토 |
| 오래된 P·정지 값 | 시작·자리 변경·도착은 기어/속도 모두 2초 이내 수신 조건. 실제 제어 직전에도 실제 P·차속·착좌 확인 | 오래된 P/속도·늦은 도착 회귀. 데모 속도는 실제 제어 허용에 쓰지 않음 |
| 신호 공백을 정상 0G로 오인 | 속도 만료 시 추정 중단, 조향만 만료 시 가감속만 추정. 최초 속도 한 개는 종G 측정으로 세지 않음. 데이터 없는 리포트는 기록 없음 | 누락·NaN·역순·첫 샘플 회귀 |
| 알림 누적 | 주행 중 음성/효과음 공통 간격 8초, 합계 6회·음성 최대 3회. 같은 이벤트의 소리는 하나로 통합. 억제 사유 기록 | 30분 가상 시계 혼합 입력에서 허용 요청 6회(음성 3/차임 3), 상한 억제 로그 중복 방지 |
| 미검증 열선 보온 | 양수 열선 요청을 기존 동의와 무관하게 검증 대기로 차단. 30/45분 가정을 안전 타이머로 구현하지 않음 | 호스트 정책 검사 및 Pleos 어댑터 제한 |
| 이미 실은 뒤 시작·중간 정차 | 홈의 최근 VIP에서 바로 시작. 자동 제안 억제 초기화 버튼. 도착 화면에서 같은 VIP로 새 이동 시작 | 새 실행 화면·상태 머신 회귀. 새 이동의 통계는 초기화 |
| 과도한 성공 표현 | 원복 결과·변경 없음·실패를 구분. ‘완벽한 배송’ 제거, ‘추정 기준’ 표시. 리포트 횟수는 허용된 안내 요청 | 화면 검수 및 no-data 리포트 회귀 |
| 데모 입력 접근 | `android.permission.DUMP` 보유 송신자로 수신 제한. 일반 제3자 앱용 입력 창구로 두지 않음 | 패키지 Manifest·adb shell 재생. 별도 악성 앱 침투시험은 수행하지 않음 |

2초·8초·3회·6회는 D등급 시제품 정책입니다. 안전 인증값이나 실사용 피로 검증 결과가 아닙니다. 주행 안내 집계는 reducer가 허용한 출력 요청이며 실제 재생 완료, 정차 안내, 외부 전화·순정 내비는 별도입니다.

- `:app:assemblePleosRelease`: 성공. 기존 release 키로 서명.
- `:app:lintPleosRelease`: 오류 0, 경고 33. 의존성/AGP 버전·미사용 리소스·기존 API/아이콘 경고가 남습니다.

- 에뮬레이터 온도 getter의 `PropertyNotAvailableException`은 `FAILED: 원래 값 읽기 실패 · 변경하지 않음`으로 표시. 공유 풍량/풍향은 유지, 이미 요청값인 열선/통풍 OFF는 변경하지 않음. 이 실행은 온도 개선·실차 복원 성공을 입증하지 않음.
- 사용자 사인·참가 정보는 Git에서 제외. 공개 DOCX에는 개인정보·동의·서명 공란 유지.

재현 명령:

```bash
./gradlew :core:test :app:assemblePleosRelease :app:lintPleosRelease
adb install -r -g apk/VIPSeat_CargoConcierge_release.apk
adb shell am start -W -n ai.vipseat.cargoconcierge/.MainActivity
```

스크린 캡처는 `demo/capture_screens.sh <apk> <출력폴더>`로 재현합니다. 여기서 반복된 기어·속도·조향 입력은 명시적 합성 시나리오이며 차량 실측값이 아닙니다.

## 남은 검증과 제품 경계

- 프로세스 종료 후 원래 설정 자동 복구는 구현하지 않았습니다. 로컬 미완료 표식은 수동 확인 안내용입니다.
- 값 비교는 외부 변경을 추정할 뿐 조작 주체를 식별하지 않습니다. 같은 값으로 수동 변경한 경우 및 SDK 읽기/쓰기 사이 경쟁은 남습니다.
- 신선도는 앱 수신 시각입니다. 센서 생성 시각·전송 지연·차종별 조향비/축거 오차를 보증하지 않습니다.
- 이 원복 강화는 제출용 Pleos 제어 경로입니다. 개발용 AOSP 직접 제어/Mock의 구현과 동일하다고 주장하지 않습니다.
- 실제 식품·포장·시트 온도, 기준 센서 대비 G, 알림 피로, 반복 사용, 지불 의향은 [실행표](검증자료/실측_사용자검증_실행표.md)에 원자료와 함께 추가해야 합니다. 결과칸은 비워 두었습니다.
- v1.0.0 영상은 당시 기록입니다. v1.1.0의 제한·실패 처리는 새 화면·본문·소스로 확인합니다.

권한 정의는 [Android DUMP 문서](https://developer.android.com/reference/android/Manifest.permission#DUMP), 제출 산출물 형식은 [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)를 참고했습니다.
