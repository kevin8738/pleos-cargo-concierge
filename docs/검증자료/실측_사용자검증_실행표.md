# VIP 조수석 — 실측·사용자 검증 실행표

작성일 2026-10-29. **상태: 실행 계획. 결과칸은 비워 둔다.** 현재 검토한 제출 자료에는 아래 현장 실측·사용자 조사·구매 인터뷰 결과가 포함되지 않았다. 이는 실제 시험이나 인터뷰가 한 번도 없었다는 판정이 아니다. 기존 기록이 있다면 원자료와 조건을 확인해 연결하고, 확인하지 못한 값을 추정해 채우지 않는다.

이 문서의 표본 수·횟수·기간·통과선은 모두 **D등급 팀 의사결정 기준**이다. 탐색 단계의 범위 축소·재시험에 쓰며 통계적 유효성, 식품 보존, 물건·사람의 안전을 인증하지 않는다. 앱 단위 테스트, SDK 호출, 실차 상태, 물리 효과, 사용자 행동을 별도 증거로 보고한다.

실행용 대본·빈 CSV는 [현장검증 진행 키트](현장검증_진행키트/README.md)에 있습니다. 운전자·짐·측정 장비는 확보하지 못해 실행 준비까지만 진행합니다. 현재 v1.1.4/code7의 코어158·앱24=182시험, 제어10판정, 동선9판정은 별도 소프트웨어 증거입니다([현재 검증](../검증_v1.1.4.md) · [원자료](AVD_v1.1.4/README.md)). 실제 에뮬레이터 음향 대조·내비 비전면 콜백·합성 경계 계산도 관측 범위를 구분하며 아래 현장 결과칸을 채우지 않습니다. APK해시·82.287311초 영상·4.49G 합성 출력은 [현재 근거 색인](../근거_EVIDENCE.md)에 연결합니다. 이전 v1.1.3의161건/3.69G와 v1.1.2의138건/4.53G, [v1.1.1 제어 확인](AVD_v1.1.1/README.md)도 해당 버전 이력으로 보존합니다.

## 1. 실행 순서와 기록 원칙

1. 제어·복원 회귀 결과를 확인한 뒤 허용된 시험 환경의 차량 상태를 대조한다. 잘못된 값 복원·확인 없는 완료 표시가 남으면 제어를 포함한 사용자 파일럿을 보류한다.
2. 정지 시험대에서 포장·온도를 비교한다. 가감속 비교는 폐쇄 시험 공간에서 시험 담당자가 수행하고, 승객의 기기 조작으로 운전자의 주의를 끌지 않는다. 실제 도로에서 물건을 쏟거나 급제동을 유도하지 않는다.
3. 정차 사용성 과업을 먼저 진행하고, 이후 일상 포장음식 운반 기회를 관찰한다. 열선 보온·반려동물 운반은 일반 파일럿의 대표 장면에서 제외한다.
4. 불리한 결과·중단·누락도 기록한다. 원자료·날짜·환경이 확인된 결과만 근거표에 추가하고, 설정값을 실측값으로 바꾸어 쓰지 않는다.

아래 날짜·공수는 D등급 내부 계획이다. 역할의 실담당자·확보일은 정해진 뒤 공통 기록표에 적으며 현재 확보된 것으로 세지 않는다. 외부 연락·참여 모집은 실행 준비와 별개의 작업이다.

## 2. 제어를 끝내는 동작

각 조건을 Mock 및 지원되는 AVD에서 3회 재현한 뒤, 실차 허용 범위에서 확인한다. Mock·AVD 성공을 실차 확인으로 올리지 않는다. 각 행에서 **요청 전 값, 앱 요청값, 요청 수락, 이후 읽힌 값·시각, UI 문구**를 남긴다. 온도는 설정값과 실제 센서 온도를 구분하며, 전원·좌우 동기화 상태와 운전석 설정 변화도 별도 기록한다. 설정값 일치만으로 냉방 작동·보호 효과를 판정하지 않는다. 코드 회귀 테스트가 이미 수행됐다면 그 결과 파일을 별도 연결하고 현장 결과칸을 대신 채우지 않는다.

| 조건 | 기대 동작·판정 기준 | 환경·반복·실제 결과 | 근거 파일 |
|---|---|---|---|

| 공조 전원·좌우 동기화 | 전원 ON/OFF와 설정값 일치를 별도로 기록. 동기화 상태 확인 후 허용된 온도 요청만 실행하며 운전석 값·동기화 상태의 전후를 대조. 자동 전원 ON으로 시험을 통과시키지 않음 | | |

**결정:** 잘못된 복원 또는 확인 없는 완료 표시가 1건이라도 있으면 해당 제어 범위를 제한하고 수정 후 같은 조건으로 재시험한다. 값 변화만으로 조작 주체를 특정하지 않는다. `restore 요청 성공`과 `관측값 일치`는 별도 결과다.

미확인·착좌와 구별 불가능·오류는 설정 보류로 남긴다. **‘사람이 없다’는 사용자 체크로 보류를 우회하지 않는다.** 이때 유효 신호로 코칭·챙김을 사용하는 흐름을 관찰한다. 지원표에는 차종뿐 아니라 시험한 하중·바닥·배치·좌석과 이유를 연결하고 관찰하지 않은 조합으로 확대하지 않는다. 원시값 접근이 없으면 SDK Boolean을 원시 점유값처럼 기록하지 않는다.

## 3. 케이크·포장 조건과 온도

### 정지 기울기 시험

동일 상자·동일 하중으로 **시트 표면 2종 × 고정 유무 2조건 × 5회**를 우선 비교한다(D). 실제 사용 조건과 다르면 결과 범위를 그 시험 조합에 한정한다. 매회 각도를 천천히 증가시키고 처음 미끄러진 각도, 상자 이동거리, 하중 이동을 기록한다. `tan(시작 각도)`는 해당 접촉 조건의 정지마찰계수 추정이며 차량 주행 G의 직접 측정이 아니다. 실제 케이크 내부 밀림은 별도 모형/시료와 관찰 절차가 확보된 경우에만 측정한다.

| 조건·반복 | 상자/하중·시트·고정 | 시작 각도·각도계 오차 | 상자 이동 / 내부 밀림 구분 | 원자료 |
|---|---|---|---|---|
| | | | | |

**결정:** 반복별 최솟값과 산포를 보고한다. 한 시험의 마찰계수로 0.15G의 케이크 파손 예방 효과를 확정하지 않는다. 시험 조건에서 현재 프리셋보다 낮은 가속에 대응하는 미끄러짐이 관찰되면 그 조건의 한계값을 재검토하고 고정 수단을 우선 안내한다.

### 상자 내부·주변 온도 비교

같은 차·같은 위치·포장·하중·송풍 조건에서 **기본 공조(A)와 케이크 프리셋(B)을 각 20분, 3쌍** 비교한다(D). 각 쌍의 순서를 A→B, B→A, A→B로 바꾸고 같은 초기 상태로 되돌린다. 시작 상자 내부 온도 차 ≤0.5℃, 시작 실내/외기 차 ≤1℃를 초기 매칭 기준(D)으로 두며 벗어나면 별도 조건으로 기록한다. 일사·차량 정차/주행·풍향·공조 공유 존 여부를 함께 기록한다. 센서 하나는 상자 안, 하나는 상자 밖 같은 높이에 두며 식품 온도로 표기하지 않는다. 앱의 ‘평균 설정 온도’는 `getHvacTemperature/registerHvacTemperature`로 받은 설정값의 평균이며 이 물리 계측값으로 대체하지 않는다. 전원·좌우 동기화·송풍 상태는 시험 조건으로 기록한다.

|---|---|---|---|---|
| 1 / A→B | | | | |

**월 활성 차량 계산의 경계:** 호환·배포·실제 도달이 확인된 차량 수 N은 미확인이다. 기획서의 N=10,000 정규화 예는 월 기회 비율×해당 차량 설치 비율×설치·기회 보유 차량의 월 완료 비율을 낮은/기준/높은 가정(D)으로 곱한 15/84/275대이며 실제 예상 보유 대수·매출·제어 이용량이 아니다. 판매량을 N으로 환산하지 않는다. 월 1회 이상 유효 세션을 완료한 중복 제거 차량이라는 MAU 정의로 실제 기록을 확보한 뒤 계산한다.

**주 지불 가설:** 차량 제조사·플랫폼 서비스 상품 조직의 기능 도입. 구매 검토자 **5명(D)**에게 과거 구매 과정·예산 주체·검증·지원 조건을 비유도 질문으로 확인한다. 접촉·회의·호감을 지불 의향으로 세지 않는다.

| 익명 조직/역할 | 예산·구매 결정자 | 필요한 실차/사용자 증거 | 유료 검증 조건·단위·범위 | 다음 단계 합의·기록 |
|---|---|---|---|---|
| | | | | |

유료 검증의 제안 단위는 **승인된 차량/트림·SDK/서비스 조합 × 합의 기능 × 고정 시험표**다. APK·재현 절차·원자료·지원표·한계 보고서의 인수 범위를 협의할 수 있다. 연동/유지보수 개발·시험 차량/계측기·분석·채널 운영·장애 대응/고객 지원 비용은 항목으로 확인하며 자료 없이 금액을 채우지 않는다. 권한 미확보, 잘못된 복원·거짓 완료, 반복 사용 가치 부족, 예산·유지보수 미확보는 중단·축소 조건이다. 이는 계약 설계 가설이며 계약·가격·원가·구매 의향 결과가 아니다. 과거 업무용 센서판 월 1만 원 가정은 현재 검증 계약·라이선스 가격에 사용하지 않는다.

**내재화와 도입 비교 질문:** 구매자가 직접 만들 때와 품목 근거·복원 예외 로직·SDK 해석 기록·시험표를 인수할 때의 개발·실패 분석 시간, 변경 대응 책임, 검증 비용을 어떤 자료로 비교하는지 묻는다. 팀 자산이 시간을 줄인다는 것은 가설이며 기술 독점성·구매 의향으로 기록하지 않는다. 후속 라이선스는 실차 인수 기준·기회별 고객 가치·SDK 재시험 책임·지원 기간·예산이 합의된 경우에만 검토한다. App Market 수익 구조와 무료 소비자 배포의 운영 재원도 미확인 항목으로 남긴다.
