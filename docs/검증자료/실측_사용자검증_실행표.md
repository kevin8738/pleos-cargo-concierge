# VIP 조수석 — 실측·사용자 검증 실행표

작성일 2026-10-29. **상태: 실행 계획. 결과칸은 비워 둔다.** 현재 검토한 제출 자료에는 아래 현장 실측·사용자 조사·구매 인터뷰 결과가 포함되지 않았다. 이는 실제 시험이나 인터뷰가 한 번도 없었다는 판정이 아니다. 기존 기록이 있다면 원자료와 조건을 확인해 연결하고, 확인하지 못한 값을 추정해 채우지 않는다.

이 문서의 표본 수·횟수·기간·통과선은 모두 **D등급 팀 의사결정 기준**이다. 탐색 단계의 범위 축소·재시험에 쓰며 통계적 유효성, 식품 보존, 물건·사람의 안전을 인증하지 않는다. 앱 단위 테스트, SDK 호출, 실차 상태, 물리 효과, 사용자 행동을 별도 증거로 보고한다.

실행용 대본·빈 CSV는 [현장검증 진행 키트](현장검증_진행키트/README.md)에 있습니다. 현재 운전자·짐·측정 장비는 확보하지 못해 준비까지만 완료했습니다. 최신 [AVD 제어 확인](AVD_v1.1.1/README.md)은 별도 소프트웨어 증거이며 아래 현장 결과칸을 대체하지 않습니다.

## 1. 실행 순서와 기록 원칙

1. 제어·복원 회귀 결과를 확인한 뒤 허용된 시험 환경의 차량 상태를 대조한다. 잘못된 값 복원·확인 없는 완료 표시가 남으면 제어를 포함한 사용자 파일럿을 보류한다.
2. 정지 시험대에서 포장·온도를 비교한다. 가감속 비교는 폐쇄 시험 공간에서 시험 담당자가 수행하고, 승객의 기기 조작으로 운전자의 주의를 끌지 않는다. 실제 도로에서 물건을 쏟거나 급제동을 유도하지 않는다.
3. 정차 사용성 과업을 먼저 진행하고, 이후 일상 포장음식 운반 기회를 관찰한다. 열선 보온·반려동물 운반은 일반 파일럿의 대표 장면에서 제외한다.
4. 불리한 결과·중단·누락도 기록한다. 원자료·날짜·환경이 확인된 결과만 근거표에 추가하고, 설정값을 실측값으로 바꾸어 쓰지 않는다.

## 2. 제어를 끝내는 동작

각 조건을 Mock 및 지원되는 AVD에서 3회 재현한 뒤, 실차 허용 범위에서 확인한다. Mock·AVD 성공을 실차 확인으로 올리지 않는다. 각 행에서 **요청 전 값, 앱 요청값, 요청 수락, 이후 읽힌 값·시각, UI 문구**를 남긴다. 코드 회귀 테스트가 이미 수행됐다면 그 결과 파일을 별도 연결하고 현장 결과칸을 대신 채우지 않는다.

| 조건 | 기대 동작·판정 기준 | 환경·반복·실제 결과 | 근거 파일 |
|---|---|---|---|
| 정상 도착·수동 종료 | P단·정차 조건에서 원래 값이 확인된 항목만 복원 요청. 요청 수락과 상태 확인을 구분 | | |
| 보호 중 외부 설정값 변경 | 현재값과 앱 마지막 설정값이 다르면 외부 변경/출처 불명으로 다룸. 사용자의 변경이라고 단정하지 않고 과거 값 덮어쓰기 방지 | | |
| 원래 값 읽기 실패 | 출처·시각이 확인된 대체값이 없으면 임의 기본값으로 복원하지 않음. 미확인 상태 표시 | | |
| 복원 거절·타임아웃·읽기 실패 | 완료 표시를 하지 않음. 실패/확인 필요 상태와 수동 확인 방법이 맞음 | | |
| 보호·복원 도중 앱 종료와 재시작 | 재시작으로 중복 제어·임의 복원이 생기지 않음. 복구할 정보와 확인하지 못한 정보를 구분 | | |
| 주행 상태의 종료·착좌 이벤트 | 허용되지 않은 상태에서 제어가 실행되지 않음. 보류·종료 상태를 실제 동작과 일치시킴 | | |
| 중간 매장 정차와 재진입 | 경유지 이벤트의 유지와 P단·정차·운전석 문 열림의 종료를 구분. 도착 화면의 같은 VIP 다시 시작 또는 최근 VIP로 새 세션 시작 가능. 이전 통계는 초기화 | | |
| 부분 지원·공유 존·권한 회수 | 미지원·유지·오류를 분리. 운전석 공유 존이나 미지원 항목에 완료 효과를 표시하지 않음 | | |

**결정:** 잘못된 복원 또는 확인 없는 완료 표시가 1건이라도 있으면 해당 제어 범위를 제한하고 수정 후 같은 조건으로 재시험한다. 값 변화만으로 조작 주체를 특정하지 않는다. `restore 요청 성공`과 `관측값 일치`는 별도 결과다.

## 3. 케이크·포장 조건과 온도

### 정지 기울기 시험

동일 상자·동일 하중으로 **시트 표면 2종 × 고정 유무 2조건 × 5회**를 우선 비교한다(D). 실제 사용 조건과 다르면 결과 범위를 그 시험 조합에 한정한다. 매회 각도를 천천히 증가시키고 처음 미끄러진 각도, 상자 이동거리, 하중 이동을 기록한다. `tan(시작 각도)`는 해당 접촉 조건의 정지마찰계수 추정이며 차량 주행 G의 직접 측정이 아니다. 실제 케이크 내부 밀림은 별도 모형/시료와 관찰 절차가 확보된 경우에만 측정한다.

| 조건·반복 | 상자/하중·시트·고정 | 시작 각도·각도계 오차 | 상자 이동 / 내부 밀림 구분 | 원자료 |
|---|---|---|---|---|
| | | | | |

**결정:** 반복별 최솟값과 산포를 보고한다. 한 시험의 마찰계수로 0.15G의 케이크 파손 예방 효과를 확정하지 않는다. 시험 조건에서 현재 프리셋보다 낮은 가속에 대응하는 미끄러짐이 관찰되면 그 조건의 한계값을 재검토하고 고정 수단을 우선 안내한다.

### 상자 내부·주변 온도 비교

같은 차·같은 위치·포장·하중·송풍 조건에서 **기본 공조(A)와 케이크 프리셋(B)을 각 20분, 3쌍** 비교한다(D). 각 쌍의 순서를 A→B, B→A, A→B로 바꾸고 같은 초기 상태로 되돌린다. 시작 상자 내부 온도 차 ≤0.5℃, 시작 실내/외기 차 ≤1℃를 초기 매칭 기준(D)으로 두며 벗어나면 별도 조건으로 기록한다. 일사·차량 정차/주행·풍향·공조 공유 존 여부를 함께 기록한다. 센서 하나는 상자 안, 하나는 상자 밖 같은 높이에 두며 식품 온도로 표기하지 않는다.

| 비교쌍·순서 | 시작 조건·설정 적용 결과 | 20분 내부/주변 온도 A·B | 센서 오차·누락 | 원자료 |
|---|---|---|---|---|
| 1 / A→B | | | | |
| 2 / B→A | | | | |
| 3 / A→B | | | | |

**결정:** 측정기 사양·교정값에서 정한 두 측정의 불확도 합을 기록한다. 내부 온도 차가 그 범위보다 작거나 3쌍의 방향이 일관되지 않으면 온도 개선 효과를 주장하지 않는다. 효과가 나타나도 해당 조건의 상자 내부 공기 차이만 보고하며 냉장 보관·식품 안전 시간으로 확장하지 않는다. 열선 30/45분은 검증된 안전 타이머가 아니며 이 시험으로 승인하지 않는다.

## 4. 추정 오차·신호 품질·전체 알림

폐쇄 시험 공간에서 차량 좌표축에 고정한 기준 센서와 앱 입력·출력을 같은 시각으로 맞춘다. 축거·조향비·센서 위치·오차·샘플링률을 기록한다. 완만한 가속·감속·좌선회·우선회 각 5회(D)를 비교하고 수직 충격·타이어 슬립 조건으로 일반화하지 않는다. 시간 보정값을 기록하며 결과가 좋아지도록 시행마다 임의로 정렬하지 않는다.

| 조건 | 측정할 값 | 초기 판정 기준(D) | 실제 결과·원자료 |
|---|---|---|---|
| 4개 주행 조건 × 5회 | 정렬 후 G 절대오차의 95백분위, 부호·축, 시간차, 누락률 | 조건별 95백분위 오차 ≤0.03G·시간차 ≤0.5초 | |
| 입력 지연·손실·권한 회수 | 원시 신호 나이, 갱신 중단 시각, 코칭 중단/재개 시각 | 유효성 기준을 벗어난 입력으로 정상 코칭을 계속하지 않음 | |
| 30분 관찰 × 3회 | 효과음, 관성·경로·상태·도착 음성, 순정 내비, 음성 중첩, 사용자 음소거 이유 | 앱 주행 코칭·효과음 합계 ≤6회/30분, 앱·내비 음성 중첩 0건 | |

총 안내 횟수는 **앱 효과음 + 모든 앱 음성 + 순정 내비**로 제시하고, 주행 중/정차 후·종류별 횟수도 나눠 적는다. 도착·상태 음성을 6회 정책 평가에서 제외하더라도 총계에서 빠뜨리지 않는다. 앱에서 외부 음성 우선순위를 알 수 없는 경우 관찰 결과와 플랫폼 제약을 함께 보고한다.

**결정:** 오차·지연 기준 미달 조건은 원인을 보정하고 재시험한다. 충족 전에는 그 조건에서 추정 G 기반 코칭 성능을 주장하지 않는다. 횟수 초과·중첩이 관찰되면 알림 정책을 축소해 다시 검증한다. 단순히 알림을 줄인 결과를 물건 보호 효과로 보고하지 않는다.

## 5. 정차 과업과 4주 재사용

초기 탐색 참여자 **8명(D)**을 목표로 한다. 참가자는 대상 차량 이용 조건을 갖춘 포장음식 픽업 운전자이며, 모집 수·완료 수·중도 중단을 구분한다. 정차 과업에서는 진행자가 처음에 조작법을 설명하지 않고 도움을 요청하거나 중대한 오해가 생긴 시각을 기록한다.

| 정차 과업 | 성공 기준 | 성공 인원/시도 인원·시간 | 오해·도움·원자료 |
|---|---|---|---|
| 이미 케이크를 실은 뒤 앱 시작 | 자동 도어 제안 없이 직접 품목·자리 선택, 적용 항목 설명 | | |
| 미지원 자리·공유 존 | 바뀐 설정과 유지·미지원 설정을 정확히 구분 | | |
| 중간 매장 정차 후 출발 | 종료 상태를 이해하고 최근 VIP로 새 세션 시작 | | |
| 종료·복원 실패 확인 | 복원 요청과 확인 완료를 구분하고 필요한 수동 확인을 설명 | | |

초기 통과선은 과업별 **7/8명 성공, 지원·미지원 및 복원 상태의 중대한 오해 0건(D)**이다. 중대한 오해는 미지원 제어가 적용됐다고 믿거나, 확인되지 않은 복원을 완료로 믿고 다음 행동을 하는 경우다. 실패하면 화면·문구·동선을 수정하고 새 참여자 또는 학습 효과를 구분한 재시험을 수행한다.

이어 **4주(D)** 동안 포장음식·케이크·기타 운반 기회마다 참여자가 기록한다. 실제 관찰일 수와 누락일 수를 남긴다. 안전한 정차 상태에서 사후 기록하며 주행 중 입력을 요구하지 않는다.

| 익명 코드·날짜·품목 | 운반 기회 여부·자리 지원 | 시작/완료 여부 | 미사용·중단·음소거 이유 | 원자료 |
|---|---|---|---|---|
| | | | | |

- **기회 대비 사용률:** 기록된 운반 기회 중 세션 시작 횟수. 운반 기회가 없는 사람의 0회를 기회 분모에 더하지 않는다. 포장음식 반복 사용은 기회가 2회 이상인 참여자에서 따로 본다.
- **반복 사용의 탐색 결정선:** 포장음식 운반 기회 2회 이상인 참여자가 6명 이상이고, 그중 4명 이상이 두 번째 이후에도 자발적으로 시작하면 후속 파일럿을 진행한다(D). 기회 확보가 부족하면 불합격으로 단정하지 않고 관찰 기간을 연장한다. 충족해도 모집단 재사용률의 증명으로 쓰지 않는다.
- **D30:** 첫 세션 완료 참여자 중 28~34일에 재시작한 참여자 비율. 40%는 D등급 목표다. 운반 기회가 없는 참여자도 분모에 유지한다. 관찰 누락은 별도로 적고, 기회가 있는 참여자의 사용률을 보조 지표로 함께 제시한다. 4주 기록과 별도로 34일까지 확인한다.
- **세션 완료:** 종료 및 적용/복원 상태 확인까지 마친 상태. 미지원만 있는 세션의 완료를 제어 성공으로 세지 않고, 복원 미확인은 별도 상태로 남긴다.

## 6. 채널·설치 퍼널·지불 가설

**주 목표:** 마켓 배포 가능 시점부터 8주간 지원 차량 1,000대 설치(D). QR/광고 조회, 사람, 차량, 세션을 섞지 않는다. 참여 동의하에 부여한 차량별 익명 코드로 중복·재설치를 제거하며, 개인정보를 추가 수집하는 분석 기능은 별도 설계한다.

| 단계 | 정의·예정 경로 | 실제 수·기간·근거 |
|---|---|---|
| 유효 노출 | 지원 차량을 가진 참여자에게 설치 안내가 도달한 첫 노출을 차량 기준 중복 제거 | |
| 휴대폰 QR 안내 | 지원 차종·범위 설명. 조회 수는 참고량이며 차량 설치가 아님 | |
| 차량 설치 | 사용자가 차량 App Market에서 검색·설치. 등록·검색·권한 경로 확인 필요 | |
| 첫 시작 | 정차 중 품목·자리 선택으로 첫 세션 시작 | |
| 첫 완료 | 차량별 첫 세션 종료 및 적용/복원 상태 확인 완료 | |

노출→설치 3%와 설치→첫 완료 60%는 모두 D등급 가정이다. 1,000설치에는 `1,000 / 0.03 = 33,333.33…`대분 유효 노출, 정수 올림 **33,334**가 필요하고 계산상 첫 완료는 **600대**다. 첫 완료 1,000대가 목표라면 `1,000 / (0.03 × 0.60) = 55,555.55…`, 정수 올림 **55,556**대분 노출이 필요하다. 설치 약 1,667대는 중간 기대량이며 두 번 반올림한 값을 정확한 전환 전망으로 취급하지 않는다.

휴대폰 QR로 원격 차량 설치가 된다고 가정하지 않는다. 시장 등록·차량 검색·설치가 확인되지 않으면 시험 환경의 안내 사용성까지만 검증하고 대규모 유입을 집행하지 않는다.

| 탐색 채널·접촉 목표(D) | 2주 지원 차량 접점 | 중복 제거 유효 노출 | 차량 설치 / 첫 완료 | 운영·지원 비용 | 8주 확보 가능량·근거 |
|---|---|---|---|---|---|
| 픽업 매장 2곳 | | | | | |
| 차종 커뮤니티 1곳 | | | | | |
| App Market 노출: 승인·추천 여부 미확인 | | | | | |

채널별 확보량과 중복을 확인한 뒤 합산한다. 필요한 노출량을 지지하지 못하면 기간·설치 목표를 줄인다. 제휴 목표·조회 수·생성 영상의 반응을 지원 차량 수로 대체하지 않는다.

**주 지불 가설:** 차량 제조사·플랫폼 서비스 상품 조직의 기능 라이선스 구매. 구매 검토자 **5명(D)**에게 사용자가 반복해서 쓴다는 증거 외에 어떤 계약·지원·책임 조건이 필요한지 묻는다. 단순한 호감·회의 수락을 지불 의향으로 세지 않는다.

| 익명 조직/역할 | 예산·구매 결정자 | 필요한 실차/사용자 증거 | 유료 파일럿 조건·가격 논의 | 다음 단계 합의·기록 |
|---|---|---|---|---|
| | | | | |

예산 담당자와 유료 검증 조건이 확인되기 전에는 라이선스 매출을 예측하지 않는다. 후속 업무용 센서 연동판의 대당 월 1만 원은 기존 D등급 가격 가설이며 주 라이선스 가격·확정 고객 단가가 아니다.
