# 구매·채널 인터뷰 질문

기준: [기존 실행표 §6](../실측_사용자검증_실행표.md). 구매 검토자 5명, 매장 2곳·커뮤니티 1곳의 탐색 목표는 기존 **D 기준**이다. 아래 질문만으로 면담을 수행한 것으로 기록하지 않는다. 조직명·실명·연락처 대신 익명 조직/역할 코드를 쓴다.

## 시작

> 차량에서 운반하는 짐을 기준으로 코칭하고, 지원되는 설정의 적용·복원 상태를 보여 주는 앱의 도입 조건을 조사하고 있습니다. 현재 구현과 아직 검증하지 못한 효과를 구분해 설명하겠습니다. 먼저 현재 업무와 판단 기준을 듣고 싶습니다.

처음부터 가격·예상 매출·“안전해진다”는 효과를 제시하지 않는다. 질문에 대한 실제 사례와 확인 가능한 근거를 요청하고, 모르는 답은 미확인으로 남긴다. 녹음 등 기록 범위는 사전에 확인한다.

| B5 | 차량·버전별 지원, 업데이트, 장애 대응과 책임 범위를 어떻게 정하나요? | 공급자의 수행 범위와 운영 비용 요인 |

| B7 | 비용을 평가할 때 어떤 과금 단위와 예산 범위를 사용하나요? 답하기 어렵다면 결정 절차를 알려 주세요. | 차량/기능/기간 등 단위, 출처, 범위·미확인 여부 |

가설 설명 뒤에는 “이 설명 중 도입 판단에 관련 없는 부분과 빠진 부분은 무엇인가요?”라고 묻는다. 기존 D 가격을 상대 답변처럼 기록하지 않는다. 예산 담당자·유료 조건이 확인되기 전 매출을 확정하지 않는다.

수량 답변에는 기간·단위·집계 방법·근거·중복 여부를 함께 적는다. 2주 탐색 채널을 전체 유통 능력으로 해석하거나 조회수를 지원 차량 설치로 변환하지 않는다. 8주 1,000설치와 필요 노출 산식은 과거 D 계산 예이며 현재 확보 약속이나 답변자의 보장 수량이 아니다. 접점·권한·예산이 확인된 범위에서만 확대를 판단한다.

## 기록과 마무리

`05_인터뷰답변.csv`에 질문마다 답변·관찰 사실·진행자 해석·근거 상태를 나눠 쓴다. 거절·무응답·알 수 없음도 남긴다. 마지막에 “제가 이해한 내용 중 다른 점이 있나요?”라고 확인한다. 후속 행동을 실제 합의했을 때만 `agreed_next_step`에 적고, 감사·호감·회의 수락을 지불 의향으로 세지 않는다.
