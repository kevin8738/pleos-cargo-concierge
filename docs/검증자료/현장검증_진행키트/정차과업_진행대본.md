# 정차 과업 진행 대본

기준: [기존 실행표 §5](../실측_사용자검증_실행표.md). 본 대본은 **정차 상태의 실제 사용자 관찰**용이다. Mock·상태 화면을 사용하면 해당 과업의 `state_origin`에 표시한다. 실행하지 못한 상태를 진행자가 사실처럼 설명하거나 실차 성공으로 합산하지 않는다.

## 준비와 시작 멘트

앱 버전·APK 해시, 차량/AVD/Mock 환경, 시험 범위, 기록 동의를 `01_실행세션.csv`에 확인한다. 기기 설정은 진행자가 미리 준비하고 원래 상태와 관찰 구간을 기록한다. 필요한 실패 상태를 실차에서 임의로 만들지 않는다. 원값 실패·복원 실패 화면은 검증된 시험 경로나 표시된 시나리오로 제시한다.

> 오늘은 사람의 능력이 아니라 앱의 설명과 동작을 확인합니다. 평소라면 어떻게 하실지 보여 주시고, 생각나는 점을 말씀해 주세요. 막히거나 그만하고 싶으면 알려 주세요. 조작 방법은 먼저 설명하지 않겠습니다. 이 과정은 정차한 상태에서 진행합니다.

동의 범위 밖의 녹음·화면 촬영은 하지 않는다. 과업 순서는 아래대로 쓰되 순서를 바꾸면 기록한다. 전 과업에서 익힌 내용과 진행자의 설명을 다음 과업의 사전 경험으로 남긴다. 과업 시간은 안내 종료→참가자의 완료/포기까지이며 도움 시간도 포함한다.

## T1 · 이미 싣고 시작

**준비:** 이미 조수석에 케이크 상자를 실은 상황. 앱 시작 전 도어 제안이 없고, 아직 보호 세션이 시작되지 않은 상태다. 정차 화면 또는 표시된 Mock에서 실행한다.

> 케이크를 조수석에 실었습니다. 출발 전에 이 앱을 사용하려고 합니다. 시작해 주세요. 끝났다고 생각하면 알려 주세요.

완료 선언 후 묻는다.

> 지금 무엇이 시작됐고, 차량에서 어떤 설정이 바뀌었거나 그대로라고 생각하나요? 그렇게 판단한 화면을 알려 주세요.

**관찰:** 직접 품목·자리 선택 여부, 적용/유지/미지원 구분, 조작 수, 시작 지연, 도움 요청. 최근 VIP가 이미 저장돼 있으면 그 사용을 기록한다. 최근·추천 VIP는 현재 자리에서 1탭, 자리 변경은 추가 1탭이라는 UI 경로가 이미 있다. 이를 실제 사용자의 조작 수·성공률로 미리 기록하거나 진행자가 먼저 설명하지 않는다. ‘설정값 확인’을 공조 작동·상자 온도 확인으로 오해하는지도 기록한다.

## T2 · 부분 지원 또는 공유 존

**준비:** 실제로 미지원/공유 존이 확인되는 시험 환경 또는 명시된 Mock 상태. 어느 항목이 지원되고 유지되는지 진행자용 정답을 사전에 근거 파일과 연결한다.

> 이 자리에서 이 짐을 위한 준비를 해 주세요. 화면을 보고 지금 가능한 일과 확인이 필요한 일을 설명해 주세요.

중립 후속 질문:

> 어떤 정보로 그렇게 판단하셨나요? 이 상태로 출발하기 전에 확인하고 싶은 것이 있나요?

**관찰:** 미지원 항목을 적용 완료로 믿는지, 공유 설정 유지를 실패/개인 설정 변경과 혼동하는지, 앱이 실제로 하지 않은 동작을 기대하는지. 진행자가 정답을 설명한 뒤의 성공은 독립 성공으로 세지 않는다.

## T3 · 중간 매장 정차 후 새 이동

**준비:** 세션 진행 후 P단·정차·운전석 문 열림으로 종료된 상태를 확인한다. 내비 경유지 이벤트만으로 유지되는 경우와 섞지 않는다. 이 과업에서는 실제/시험 입력 중 어떤 이벤트를 썼는지 기록한다.

> 중간 매장에 잠시 들렀고, 차에는 같은 짐이 남아 있습니다. 돌아와서 다음 목적지로 출발하려고 합니다. 지금 상태를 확인하고 필요하다고 생각하는 행동을 해 주세요.

완료 선언 후:

> 이전 이동과 지금 이동은 어떻게 이어진다고 생각하나요? 화면에서 확인한 내용을 설명해 주세요.

**관찰:** 종료 이해, 같은 VIP 다시 시작/최근 VIP로 새 세션 시작, 이전 통계·알림 예산 초기화 이해, 자동 유지 기대. 기존 앱에 없는 정차 유지 시간을 안내하지 않는다. 필요 시간이 나오면 사용자의 요구로 적는다.

## T4 · 종료·복원 확인 실패

**준비:** 지원되는 시험 경로에서 복원 확인 실패가 표시된 상태. 현재값을 모르는 경우 그대로 두며 성공값을 만들어 넣지 않는다. 프로세스 재시작 표식만 제시한다면 원래 온도·앱 설정값은 보존되지 않는 현재 범위와 맞춘다. 실패 화면만 제시하면 `state_origin=상태시안`으로 구분한다.

> 이동을 마친 뒤 이 화면이 나왔습니다. 지금 상태를 설명하고, 다음에 어떻게 하실지 보여 주거나 말해 주세요.

후속 질문:

> 어떤 항목이 확인됐고 어떤 항목이 아직 확인되지 않았나요? 차량 설정을 확인한다면 어디에서 무엇을 확인하실 건가요?

**관찰:** 정상 확인 시 짧은 완료 표시와 실패·미확인 수동 안내의 구분, 복원 요청과 확인 완료 구분, 미확인 복원을 완료로 믿는지, 필요한 수동 확인 설명, 재시도/새 적용 보류 상태 이해. 실제 차량 설정은 진행자가 확인할 수 있는 범위에서 별도 대조한다.

## 도움·종료와 기록

도움을 요청하면 먼저 “지금 무엇을 하려고 하셨나요?”라고 묻고 질문·시각을 적는다. 더 진행할 수 없으면 필요한 설명을 제공하되 `assisted=true`로 남긴다. 중대한 오해가 다음 행동으로 이어지거나 참가자가 중단하면 관찰을 멈추고 실제 상태를 설명한다. 이해를 돕기 위해 제공한 설명을 성공 증거로 소급하지 않는다.

`02_정차과업.csv`에 실제 발언을 비식별화해 적고, 관찰과 해석을 분리한다. 성공은 기존 실행표의 과업 기준을 모두 충족했는지로 판정하며 도움 여부를 별도로 표시한다. 과업별 시도·무도움 성공·도움 후 성공·실패·중단을 함께 보고한다. 표본 목표 8명, 7/8 및 중대한 오해 0건은 **기존 D 기준**이며 빈 표본에 통과 판정을 내리지 않는다.

마지막으로 묻는다.

> 평소에는 이런 짐을 어떻게 운반하나요? 오늘 앱을 쓰면서 예상과 달랐던 점은 무엇인가요? 다음 실제 운반 때 사용할지 말지를 결정하게 하는 것은 무엇인가요?

“다음에도 쓰겠다”는 답변은 의향이다. 이후 실제 운반 기회에서 자발적으로 시작한 기록과 구별한다.
