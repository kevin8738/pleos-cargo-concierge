# 기록 규칙과 계산 범위

**현재 모든 CSV는 데이터 0행이다.** 빈 칸은 아직 확인하지 않은 값이며 0, false, 없음으로 바꾸지 않는다. 관찰 결과를 추가한 뒤에도 미실시·측정 실패·관찰 누락은 구분한다. 원자료는 지정한 로컬 경로에 두고 CSV에는 상대 경로만 연결한다.

## 공통 형식

- ID는 임의 코드이며 이름·연락처·차량번호와의 대응표를 이 폴더에 두지 않는다. `participant_id`, `vehicle_id`, `organization_id`, `operator_id`, `reviewer_id` 모두 같은 원칙이다.
- 날짜는 `YYYY-MM-DD`, 시각은 시간대를 포함한 ISO 8601이다. 계측 시각은 실행 시작 기준 초(`*_s`)를 쓴다. 값이 없으면 공란이며 시간 오차와 기준은 계측 세션에 기록한다.
- `evidence_class`: `합성입력`, `Mock`, `AVD`, `시험대`, `실차정차`, `실차폐쇄시험`, `실사용관찰` 중 실제 환경. 합성 데이터가 실제 사용자에게 제시된 경우 자극은 합성이고 사용자 행동은 실제 관찰임을 `state_origin`/`notes`에 구분한다.
- `true`/`false`는 실제로 확인한 경우만 쓴다. `unknown`은 확인할 수 없음이다. 공란은 아직 기록하지 않음이다.
- `evidence_path`와 `reference_path`는 관찰·버전·상태를 검토할 수 있는 자료 경로다. 인용문에서 사람·장소를 식별할 세부사항은 제거한다. CSV에서 수식으로 실행될 수 있는 `=`, `+`, `-`, `@`로 시작하는 자유응답은 스프레드시트에서 문자열로 가져온다.

## 01 · 실행 세션 / 02 · 정차 과업

`01`의 버전·커밋·해시는 **실제로 실행한 APK**에서 확인한다. `consent_status`는 `확인`, `거절`, `미확인`이며 `recording_scope`, `retention_rule`, `withdrawal_route`에는 실제로 합의한 범위·보관 기간·익명 코드로 요청할 경로를 적는다. 미확인 상태로 관찰을 시작하지 않는다. `participant_id`는 계측만 하는 세션에서는 비워 둘 수 있다.

`02`의 `task_id`는 T1–T4, `attempt_no`는 실제 시도 순서다. `state_origin`은 `실행상태`, `시험입력`, `상태시안`을 구분한다. `prior_exposure`에 이전 과업·재시험·도움 경험을 적는다. `duration_s`는 안내 종료부터 완료/포기까지, `action_count`는 화면 탭·버튼·선택 등 입력 횟수다. 관찰 전에 세부 계산 규칙을 정하고 세션 중 바꾸지 않는다.

`outcome`은 `무도움성공`, `도움후성공`, `실패`, `중단`, `판정불가`다. `critical_misunderstanding=true`는 미지원 제어 적용 또는 미확인 복원 완료를 믿고 다음 행동을 하는 기존 정의에 해당할 때만 기록한다. `observed_behavior`에는 관찰 사실, `interpretation`에는 연구자의 해석을 적는다. 도움 후 성공을 무도움 성공 분자에 더하지 않는다. 기존 실행표의 D 통과선은 과업별 분모·중단·도움 여부와 함께 검토한다.

## 03 · 관찰일 / 04 · 운반 기회

`03`은 참여자별 **기회 없는 날도** 한 행이다. `record_status`는 `확인완료`, `일부누락`, `누락`, `중단`이다. 확인완료이고 기회가 없으면 `opportunity_count=0`; 누락이면 공란이다. `source`는 당일 기록/사후 회상/앱 기록 등 실제 출처다. `first_completed_date`는 원자료로 확인한 최초 세션 완료 날짜이며 추정하지 않는다. 최초 완료일이나 추적 여부가 불명확한 참여자를 조용히 제외하지 말고 D30 판정불가 인원으로 함께 보고한다.

`04`의 한 행은 운반 기회 한 번이며 미사용도 포함한다. `opportunity_index`는 해당 참여자의 기록된 기회 순서다. `cargo_category`로 포장음식·케이크·기타를 나누고 `seat_support`는 `지원`, `부분지원`, `미지원`, `미확인`이다. `initiation`은 `자발`, `진행자요청`, `리마인드후`, `시작안함`, `미확인`이며 자발 재사용과 도움받은 사용을 분리한다. `session_started`, `session_completed`는 실제 확인된 상태다. 완료는 종료 및 적용/복원 상태 확인까지이며 미지원 완료를 제어 성공으로 해석하지 않는다. `restore_status`에 `확인완료`, `미확인`, `실패`, `변경없음`을 구분한다. `use_reason`, `nonuse_or_stop_reason`, `mute_reason`은 사용자의 실제 답변이며 추정이면 해석임을 표시한다.

계산은 기존 실행표 §5를 따른다. 기록된 운반 기회 대비 시작 횟수, 포장음식 기회가 2회 이상인 참여자의 두 번째 이후 자발 시작, D30을 별도로 보고한다. 관찰 누락과 0기회를 섞지 않는다. D30은 최초 완료자 중 28–34일 재시작이며 그 기간 기회가 없는 참여자도 분모에 유지한다. `03`의 날짜와 `04`의 원자료로 34일까지 확인한 후 계산한다. 빈 템플릿으로 비율을 산출하지 않는다.

## 05 · 인터뷰 답변

`interview_type`은 `구매` 또는 `채널`, `question_id`는 B1–B8/C1–C7이다. `respondent_role`은 일반화한 역할로 적는다. `answer_status`는 `답변`, `거절`, `무응답`, `알수없음`이다. `answer_summary`와 `verbatim_deidentified`는 실제 답변, `researcher_interpretation`은 해석이다. `evidence_status`는 `진술만`, `기록확인`, `미확인`이다. 수량은 `quantity_value`, `quantity_unit`, `period`, `dedup_method`를 함께 써서 차량·사람·조회·설치의 분모를 구별한다. 추가 정보가 없으면 공란으로 두며 가격이나 전환율을 대입하지 않는다.

## 06 · 계측 세션 / 07 · G 판정 표본

`06`에서 계측기 모델·정확도·영점/교정 근거, 위치·좌표축, 기준 센서와 앱 입력 주기, 고정 시간 보정값과 동기 오차를 먼저 기록한다. `sampling_rule`에는 연속 기록 중 어느 시각을 표본으로 삼는지 사전에 적고, 잘 맞는 구간만 뽑지 않는다. `decision_rule_path`에 해당 APK의 G 크기/부호/필터·상태 경계 정의를 연결한다. `window_start_s`/`window_end_s`는 실제 관찰 구간이다. `dropout_notes`는 기록 누락이며 0G가 아니다.

`07`은 고정 규칙으로 정렬한 시각 표본이다. `reference_g`와 `app_g`는 `axis_or_metric`이 같은 값이며 단위를 G로 통일한다. `reference_uncertainty_g`, `input_age_s`, `input_valid`를 함께 적는다. `preset_limit_g`와 `warning_boundary_g`는 시험 중 실제 빌드의 설정에서 확인한다. v18 심사의 0.12G×80%=0.096G, 0.15G×80%=0.12G는 계산 예이며 측정 결과·안전 한계가 아니다. 기존 p95 오차 ≤0.03G 및 시간차 ≤0.5초는 실행표 §4의 **D 기준**이며 경계 판정 성능을 대신하지 않는다.

`reference_state`/`app_state`는 같은 규칙의 `정상`, `주의`, `초과`, `데이터없음`으로 기록한다. 기준 센서 불확도가 경계를 가로지르면 `reference_state=불확정`으로 적는다. `warning_class`는 주의 이상을 양성으로 했을 때 `TP`, `FP`, `FN`, `TN`, `판정불가`; `over_class`는 초과를 양성으로 같은 방식이다. 입력이 유효하지 않거나 기준이 불확정이면 FP/FN으로 강제 분류하지 않고 별도 집계한다. 방향·조건별 원자료를 보존하며 모집단 성능으로 확대하지 않는다.

경계 위/아래의 표본과 상태 전환을 모두 포함하고 FP/(FP+TN), FN/(FN+TP)를 분모와 함께 보고한다. 이는 고정 표본 시점의 판정률이며 독립 사건 수가 아니다. 연속 오판은 별도로 사건화할 때 사전 정의한 규칙과 지속 시간을 남긴다. 경계 접근을 위해 실제 도로에서 급조작하지 않는다. 시험 환경의 합성 입력은 코드 반응 증거이며 물리 정확도 증거가 아니다.

## 08 · 실제 음향

재생 요청만 있고 소리를 확인하지 못한 경우도 행을 남긴다. `source`는 `앱효과음`, `앱관성음성`, `앱경로음성`, `앱상태음성`, `앱도착음성`, `순정내비`, `기타외부음성`이다. `request_s`와 실제 들린 `audible_start_s`/`audible_end_s`를 분리한다. `audible_status`는 `재생확인`, `미재생확인`, `확인불가`다. 소리를 듣지 못한 로그만으로 재생/미재생을 확정하지 않는다.

`trigger_crossing_s`는 기준 신호가 해당 경계를 넘은 시각이다. 실제 재생 지연은 경계 넘음→청취 시작과 요청→청취 시작을 따로 계산한다. `suppression_reason`에 쿨다운·예산·외부 음성 등의 실제 관찰/로그 근거를 적고 억제된 요청을 G 판정 누락과 혼동하지 않는다. `policy_counted`는 당시 앱 주행 정책에 포함되는지, `motion_state`는 `주행`/`정차`/`미확인`이다.

`overlap_event_ids`에는 청취 구간이 겹친 사건 ID, `overlap_s`에는 실제 겹침 시간을 적는다. `budget_exhausted_s`는 실제 로그로 확인된 공통 주행 알림 예산 소진 시각이며 여섯 번째 요청 시각으로 추정하지 않는다. 앱 전체/순정 내비/기타 음성을 종류별로 집계하고, 정책 평가 대상 및 정차 후 음성을 따로 표시한다. 기존 30분×3회·앱 주행 합계 ≤6회/30분·음성 중첩 0건은 실행표의 **D 기준**이다. 짧은 관찰의 횟수를 30분 측정 결과로 환산하지 않는다.
