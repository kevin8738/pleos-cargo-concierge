# driving-audio-01 ON 독립 증거 검수

판정: **주행·음향 관측은 유효, 원 실행·정리 실패는 보존**. 오프라인 대조 33개에서 불일치 0건이다. ADB·AVD·빌드·네트워크·원자료 편집은 하지 않았다.

50개 manifest 해시, 실행 하네스 해시, 전후 APK `8971e207…`·PID 22692, 코어 원본 해시를 확인했다. 547개 trace 중 540개 Guarding 행·180개 차속 입력이 저장 요청과 일치한다. 독립 계산의 최대 0.12354462329191915G·주행 이벤트 417개·fresh 139개가 같은 trip 14282460의 도착 보고서와 일치한다. 도착은 ARRIVED이고, 후속 정리에서 Idle/P0가 확인된다.

PCM 3,386패킷의 인덱스·WAV·해시와 각 창의 표본 수·RMS·peak를 다시 계산했다. WARN 차임 창 peak 152/RMS 12.7941, 앞선 자체 창 peak 2/RMS 1.45056이다. OVER 음성 두 창은 각각 peak 1,345/RMS 195.8587, peak 1,345/RMS 196.3952이며 앞선 자체 창 peak는 모두 2다. 이는 현재 ON 관측과 자체 기준창 대비이며 **OFF 대조는 아직 없다**.

각 주행 발화에서 저장 순서는 STOP→START→DONE이었다. STOP은 새 START 전에 있어 이 관측에서는 발화 도중 중단을 뜻하지 않는다. ERROR는 없었다. 허용 이벤트 간격은 9,980ms와 8,031ms다. host/device 시계 보정은 원계산과 일치하고 불확실성은 14.7665ms, packet/host 수신 차이는 −0.626~3.837ms다. 단일 보정에 장기 drift 보장은 없다. 수신 PCM 합본은 20.259792초이며 40.005296초 관측창의 연속 녹음 길이가 아니다. 도착 TTS 콜백은 캡처 이후이므로 이 PCM으로 도착 안내 재생까지 입증하지 않는다.

`cleanup.json`은 executionErrors=[]이고, 빈 `log.tag.MotionTrace` 원값을 복원할 때 ADB shell 인자가 사라진 오류 한 건 때문에 verified=false다. `oracle-result.json`의 유일한 issue도 cleanup not verified다. TTS·차임·데모 커브 원설정, 저장 Console 항목, Idle/P0, 서비스·알림 없음은 별도로 대조됐다. 따라서 제품 동작 실패와 구분되는 하네스 정리 실패다. 원본 result/cleanup의 false를 바꾸거나 복구 결과를 원 실행 PASS로 합치면 안 된다.

**ON 재실행은 이 정리 오류만으로 필요하지 않다.** 별도 원값 복구와 재조회 기록을 남기고 새로운 OFF 실행을 수행하면 보존된 ON과 투명하게 대조할 수 있다. 이 경우 ‘단일 두 조건 하네스가 모두 정상 종료했다’고 주장하지 않는다. 별도 복구 원자료는 이 검수 시점에 아직 없으며 후속 검토 대상이다. 새 값 0.12354G는 과거 4.49G의 원인이나 정확한 입력쌍을 소급 확인한 결과가 아니다.

재현 가능한 읽기 전용 대조 코드는 `verify_driving_on01.py`, 상세 산술과 검사 결과는 `driving-on01-verification.json`에 보관한다.
