## v2.2 현대 아이오닉 5 (2026-10-28)

- 차체를 현대 아이오닉 5(2021년형)를 묘사한 gpt-image-2 생성 참조 → **TRELLIS.2**(`microsoft/TRELLIS.2-4B`, 1024 해상도)의 형상·PBR 텍스처 생성본 `ioniq5_t2`로 교체했다. 제원 스케일·바퀴 절제·Draco 압축·메타·manifest를 적용한다. 참조는 공식 CAD나 직접 촬영 사진이 아니며, 비주얼 헐 `ioniq5_body`는 폴백으로 보관한다.
- 외형 기준은 **미러 제외 차체 전폭 1.890 × 전고 1.605 × 전장 4.635 m**(근거 **A**, [현대자동차 2021년 4월 모델 제원](https://www.hyundai.com/kr/ko/brand/brandstory/model/ioniq-history/2021-ioniq5)). 미러 포함 폭은 별도 메시 측정값이다. 실제 아이오닉 5의 축거는 3.000 m이며, 기존 비교 결과의 재현성을 위해 물리 축거 2.9 m·한계 G·코칭 규칙은 유지한다.
- **Astra**(`gpt-6-astra`, reasoning effort `max`)로 정면·후면·측면 부위 라벨을 제작하고 JSON 스키마·라벨 재그리기 일치를 확인했다. 라벨은 헐 분류와 TRELLIS.2 유리 영역 분리에 활용하고 PBR 텍스처는 유지한다. 진단 렌더와 생성 참조를 비교하는 Astra 시각 QA로 차체·등화·실내 배치를 보정한다. 점수는 모델의 시각적 비교 평가이며 실측 제품 정확도나 안전성 지표가 아니다.
- 밝은 회색 시트·트림·생성 대시보드·핸들은 일반형 설명용 실내다. 아이오닉 5 순정 실내의 정밀 재현이 아니며, 케이크는 조수석 방석 위에 배치한다. 픽셀 등화는 별도 오버레이다. 생성 메시의 패널·창문 경계에는 근사 표현이 남아 있다.
- 물리 회귀 검증(Node, 전체 코스): A 최대 0.417348 G·손상 100 %·95.4667 s·R30 39.4526 km/h, B 최대 0.117259 G·손상 0 %·133.5167 s·R30 20.8474 km/h로 기존 결과와 일치. 이는 모델 계산값(근거 C·D)이며 실차 시험 결과가 아니다. 실행 기록: `web/assets/qa/ioniq5_v22/physics_results.json`.
- **최종 검수·패킹 완료:** Metal 헤드리스 5개 진단 뷰(`front_q,rear_top,side_r,top,cabin`)에서 오류 0. 패킹본의 좌우 체이스·캐빈·지도, 4× 진행, 단독 A 복귀와 B 숨김을 확인했다. 전체 코스 검수 21개 항목 통과, 콘솔·페이지 오류 0. A/B 랩타임 95.4667/133.5167 s·최대 G 0.417348/0.117259·손상 100/0 %가 기존 물리 결과와 일치(차이 2×10⁻¹⁵ 미만). 실제 `ioniq5_t2`·PBR·분리 유리, 바퀴 4개 접지, 전후 픽셀 등화·주차 P·비교 카드·지도·단독 복귀, 소스/패킹본 JS·에셋 일치를 검증했다. Astra(max) 참조 비교와 시각 보정을 거쳤으며, 생성 패널·창문 경계의 근사 표현과 일반형 설명용 실내는 남아 있다.

## v2.1 좌우 동시 비교 (2026-10-28 저녁)
사용자 피드백 "비교가 직접적으로 안 되는 느낌 — 비교할 때는 왼쪽·오른쪽 화면으로 같이 가게". 순차(A 끝나고 3초 뒤 B) 비교를 **화면 분할 동시 주행**으로 바꿨다.
- `runner.js`: 차량 물리·G 추정·운전자·모니터·차 모델·체이스/캐빈 카메라를 한 묶음(Runner)으로. 단독 주행은 Runner A 하나, 비교는 A·B 둘이 같은 고정 스텝 dt 로 함께 돈다 → 각 차의 결과는 단독 주행과 같다.
- 레이어 분리: 차 A = 레이어 1, 차 B = 레이어 2(전조등 포함). 각 반쪽 카메라는 자기 차 레이어만 켜서 두 차가 같은 자리에서 출발해도 서로의 화면에 겹치지 않는다. 지도 카메라는 둘 다(표식 A 샴페인·B 민트).
- 렌더: 비교 중엔 시저로 좌우 반씩 2회 렌더(블룸은 생략), 지도는 전체 폭 1장. `world.update(cams[], foci[])` — 청크 컬링은 어느 카메라에든 가까우면 표시, 가로등 실제 광원 6개는 두 차에 번갈아 3개씩, 3D 가로수는 두 카메라 기준.
- `split.js` 반쪽 HUD: 위쪽 구분선 양옆에 A/B 패널(속도·G 바·총/최대 G·손상·랩타임·배지·말풍선·로그 3줄), 가운데 위 칩(거리 차 → 먼저 도착한 쪽과 남은 거리 → 랩타임 차), 도착 띠(랩타임·무사/손상·최대 G). 둘 다 서면 2초 뒤 기존 비교 카드. R/카테고리 변경은 비교를 다시 시작, A/B/C 버튼은 단독 주행으로 돌아간다.
- 검수(헤드리스): 비교 시작 → 좌우 체이스·캐빈·지도 캡처, 4× 주행, 단독 A 복귀까지 콘솔 에러 0. 물리 모듈은 그대로.

## 구현 (`js/`)
- `assets.js` AssetLibrary: manifest → GLTF+Draco, RGBE HDRI → PMREM 환경, PBR 세트(Diffuse/Normal/ARM, 반복·이방성), `instance(id)`가 실측 치수(`real_size_m` → `REAL_SIZE`)로 스케일하고 바닥 중심 피벗으로 감싼다.
- `world.js` 월드: 트랙을 따라 60 m 청크(도로 PBR·중앙선·연석·보도·건물 파사드·가로등·가로수·소품), 베이커리(간판 "달빛 베이커리", 쇼윈도, 칠판, 테이블)와 주차장, 원경 실루엣, 하늘 그라데이션+별, 가로등 SpotLight 풀 6개(가까운 2개 그림자), 320 m 밖 청크 숨김.
- `car.js` 차: 생성 차체 파트별 실제 재질(클리어코트 도장·틴팅 유리·발광 등화), 바퀴는 메타 위치에 프로시저럴, 실내는 생성 시트·대시보드·핸들 + 레이캐스트 실측 치수의 트림·필러, 조수석 품목은 분류별 생성 GLB → Poly Haven → 프로시저럴 순 폴백, 와이드 디스플레이(캔버스).
- `main.js`: 로딩 화면(진행률) → 월드 → 차 → 루프. EffectComposer(UnrealBloom 0.22, threshold 1.0) + OutputPass, 55 fps 미만 3초면 블룸 해제. QA 훅 `window.__dbgView`(차 로컬 좌표 카메라 고정), `__car`, `__scene`.
