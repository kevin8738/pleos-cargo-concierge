# v1.1.1 제어와 검증 기록

2026-10-29 · 제출 기획서 v19 · Pleos release versionCode 4

v18 재심사에서 부족했던 최신 APK의 설정 적용·재조회·복원 증거를 보완합니다. 이 기록은 공식 AVD의 소프트웨어 연동 검증이며 실제 짐 보호, 식품 온도, 주행 G 오차나 사용자 재사용을 입증하지 않습니다.

## 발견한 문제와 수정

| 문제 | 수정과 범위 |
|---|---|
| Console 비활성 상태에서 온도 원값 조회 실패 | 공식 Virtual Console을 브라우저에서 열어 DDS를 활성화하고 공조 전원을 켜서 시험 조건 준비. 원값을 못 읽으면 변경하지 않는 정책 유지 |
| Pleos SDK의 착좌 Boolean과 AOSP 원시 값 의미 불일치 | SDK 2.3.2의 getter·listener는 원시 값 1만 true로 변환. 현재 AVD의 1은 VACANT, 2는 OCCUPIED. 정확히 확인한 조합에서 true만 빈 좌석으로 인정하며 false·null은 미확인으로 처리 |
| 검증하지 않은 차량에 같은 변환 적용 위험 | SDK 2.3.2 strict 버전 고정 + Vehicle Service 2.3.22/code 74 + product crp_avd_arm64/API 34 조합만 허용. 다른 환경에서는 비착좌 확인 보류 |
| 실제 관측을 Mock 초기 상태가 덮음 | 실제 데이터 출처가 있으면 Mock의 시작 기본값을 발행하지 않음. 명시적인 데모 입력은 계속 가능하며 제어 허가의 근거로 쓰지 않음 |
| 조회 실패·지연·연결 교체 후 오래된 빈 좌석 값 사용 | 확인 상실을 null로 발행. 이전 연결 응답 차단, 더 최신 listener 보존, 제어 직전 대상 좌석 전체의 2초 이내 수신과 같은 연결 세대 재검사 |
| 적용 중 빈 좌석 확인을 잃음 | 캐빈 설정이 있는 가드를 종료하고 조건부 복원 요청. 실제 복원은 P·차속·현재값 검사. 캐빈 설정 없는 G 코칭은 유지 |
| setter 응답 직후 getter가 이전값을 잠시 반환 | 변경 전 값이 계속 보일 때만 최대 1초 안에서 100ms 간격으로 읽기 재시도. null·제3값은 실패, setter 재전송 없음, 부모 취소 전파 |

2초·1초·100ms는 D등급 구현 정책입니다. SDK raw Boolean을 단순 반전하지 않습니다. 현재 어댑터는 확정 착좌와 미확인을 구별할 수 없으므로 화면에 ‘좌석 상태 미확인·차량 설정 변경 보류’로 표시합니다. 실제 차량 지원 범위가 늘었다는 의미가 아닙니다.

## 실행 증거

코어 121개·앱 매핑 2개, 총 123개 검사 모두 실패·오류·건너뜀 0입니다. Pleos release 빌드·서명 검증을 통과했고 lint는 오류 0·경고 33입니다. 정상 왕복·착좌 보류·외부값 유지·확인 상실 복원의 AVD 4조건을 확인했습니다.

최종 실행 결과와 재현 명령은 [AVD 검증 묶음](검증자료/AVD_v1.1.1/README.md)에 기록합니다. 기존 [v1.1.0 기록](검증_v1.1.0.md)은 당시 실패 경로와 구현 이력으로 보존합니다.

## 준비만 완료한 검증

실제 참여 운전자·짐·측정 장비를 현재 확보하지 못해 [현장 진행 키트](검증자료/현장검증_진행키트/README.md)를 준비했습니다. 정차 과업 대본, 구매·채널 인터뷰 질문, 기록 규칙, 헤더만 있는 CSV 8개를 제공합니다. 데이터 행은 0개이며 참가자 관찰·인터뷰·G 계측·음향 시험을 실시한 것으로 세지 않습니다.

기준 센서와 G 오차·지연, 실제 음향 발생과 순정 내비 중첩, 사용자 과업 성공·운반 기회당 재사용·D30, 구매 예산·유료 파일럿 의사는 계속 미검증입니다. 기존 1차 목표 날짜는 장비·참여자 확보 후 실제 일정으로 갱신해야 합니다.

## 남은 한계

- HVAC 설정값 왕복은 실제 실내·상자·식품 온도 변화가 아닙니다. 공유 풍량·풍향은 유지하고 열선 ON은 검증 대기로 차단합니다.
- SDK 읽기와 쓰기 사이의 원자적 비교·교환은 제공하지 않습니다. 같은 값의 외부 조작 주체는 식별할 수 없습니다.
- 프로세스 종료 후 자동 복원은 구현하지 않았습니다. 미완료 표식은 수동 확인 안내입니다.
- 관측 신선도는 앱 수신 시각 기준이며 센서 생성 시각·실차 통신 지연을 보증하지 않습니다.
- 현재 검증 조합 외의 서비스·차종·OS는 독립 검증이 필요합니다. 차종 호환 확인을 완화하기 위해 Boolean을 반전하면 안 됩니다.
