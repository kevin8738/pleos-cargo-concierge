앱명 / 프로젝트명: **VIP 조수석 (Cargo Concierge)**

## 1. 앱 한 줄 소개
이미 실은 소중한 짐을 정차 홈에서 한 번 선택하면, 품목별 주행 코칭·도착 챙김과 지원되는 차량 설정·복원을 이어 주는 Pleos 차량용 앱입니다.

## 2. 기획 배경

**대상은 조수석에 픽업 물건을 싣는 Pleos 운전자입니다.** 가족 운전자를 우선 탐색하며, 케이크를 첫 경험으로, 퇴근길 뜨거운 포장음식을 반복 운반 장면으로 봅니다. 포장음식 주 1~2회는 팀 가정(D)입니다. 물건을 실은 뒤 설정을 확인하고, 쏠림을 조심하고, 도착해서 챙기고 설정을 되돌리는 일을 한 흐름으로 연결하려 합니다. 물건 고정과 차량 운전은 운전자가 맡습니다.

**기본 동선은 ‘선적재 → 정차 중 앱 열기 → 현재 자리의 최근·추천 VIP 1탭 → 설정 결과·코칭 → 도착 챙김·복원’입니다.** 다른 자리면 자리 선택 1탭을 더합니다. 이는 현재 UI 경로이며 실제 사용자 성과가 아닙니다. 시작은 운전자가 기억해야 합니다. 앱 실행 전 도어 이력·백그라운드 자동 호출은 미연동이고, 도어 제안은 앱이 신호를 받는 동안만 제공합니다. 따라서 검증할 가치는 **시작한 뒤 설정·운전 코칭·종료 확인의 부담을 줄이는가**입니다.

**현재 증거는 공식 AVD의 소프트웨어 실행 결과입니다.** 확인된 SDK·서비스 조합에서 설정값 왕복·활성 세션 유지·합성 G 계산·품목 선택 안내음과 주행 경고 출력을 검증했습니다(§5). P단·정차·빈 좌석·원값·항목별 지원 조건을 확인하고, 온도는 SYNC OFF까지 확인한 뒤에만 요청합니다. 실차·미확인 조합의 설정은 보류하며 유효한 신호로 가능한 코칭·챙김을 제공합니다. 설정값 재조회는 냉방 작동·짐 보호를 입증하지 않습니다. 실차 G 성능·품목 효과는 미검증이고 실제 사용자 과업 결과는 0건입니다.

**주 지불 가설은 제조사·플랫폼 서비스 상품 조직의 도입입니다(D).** 승인된 차량/SDK 조합의 구현·시험·지원 범위를 묶어 제공하는 제안이며, 구매 의향·계약·채널 결과는 없습니다(§6). 운전자에게는 매일 접속보다 **운반 기회 중 자발 시작·완료 비율**을 봅니다. 뜨거운 포장음식은 지원되는 차량 설정을 요청하는 분류이고, 음료·국물은 설정 변경 없이 코칭·챙김을 제공하는 분류로 나누어 검증합니다.

**다음 판단은 평소 방식보다 편리한지 확인하는 것입니다.** 동의한 운전자의 시작부터 종료까지 걸린 시간, 놓친 항목·상태 오해, 다음 운반 기회의 자발 사용을 비교합니다. 참가자·차량·장비 확보 후 실제 제어·G 오차·물건 상태·음향 부담을 측정하며, 현재는 빈 실행표와 CSV를 준비한 단계입니다. 사용자·실측·재사용·사업 결과 0건을 계획과 구분합니다.

| 기존 방식 | VIP 조수석이 함께 제공하려는 일 |
|---|---|
| 수동 설정·개별 음성 차량 제어 | 품목·자리 선택에 지원 항목 요청을 묶고 설정 확인·조건부 복원 결과 표시 |
| 주행 기록·운전 점수·순정 내비 안내 | 품목별 초기 한계로 짧게 코칭하고 이동 전후의 상태·최대 추정 G·안내 횟수를 같은 세션에 연결 |
| 차량 기본 하차·후석 알림(제공 차종) | 사용자가 선택한 짐의 품목·자리와 챙김·설정 복원 상태를 연결 |
| 보냉백·완충재·적재 고정 | 물리적 보호를 사용한 상태에서 설정·운전 습관·챙김 보조 |

차량의 도어·기어·차속·착좌 신호와 좌석 설정, 내비·화면·스피커를 연결하는 제안입니다. 특정 차종의 순정 기능 제공 여부를 가정하거나 스마트폰 대비 우월성·독점성을 입증한 것은 아닙니다. 별도 적재물 센서·서버 없이 구현한 연동과 실제 부담 감소의 검증을 구분합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

대표 검증은 **케이크, 음료·국물, 포장음식, 일반 짐**에 집중합니다. 구현된 보호 분류 9종은 유지하되, 꽃·반려동물·전자기기 등의 품목별 효능까지 검증한 것으로 확장하지 않습니다.

**알림과 리포트의 단위.** 6회·3회·8초는 **세션 단위의 앱 주행 안내 요청 정책**이며 실제 스피커 재생 완료나 차량 전체 소리의 상한이 아닙니다. 중간 정차 후 같은 VIP로 다시 시작해도 통계와 알림 예산을 새로 시작합니다. 30분은 검증용 관찰창이며, 그 안의 세션 수·재시작 수·누적 요청과 실제 소리·순정 내비 중첩을 따로 기록합니다. ‘30분당 최대 6회’를 코드 보장으로 사용하지 않습니다.

**시작한 세션의 유지.** 정차 중 VIP를 선택해 시작한 세션은 실행 알림을 유지하며 다른 화면에서도 이어집니다. 실행 서비스를 시작할 수 없으면 가드와 차량 요청을 시작하지 않고 이유를 표시합니다. 정상 종료는 진행 중인 차량 처리를 마친 뒤 서비스를 중지합니다. 현재 APK의 내비 전환·정상 종료·실패와 복구·비정상 종료는 §5의 실행 근거로 확인합니다. 앱 실행 전 자동 호출을 추가한 기능은 아닙니다.

**리포트의 입력 출처와 판정 범위.** 알려진 공식 AVD·Mock 입력이 포함되면 화면에 ‘모의 입력’과 ‘실주행 평가 불가’를 표시하고 계산한 최대값은 그대로 보존합니다. 0.6G 이상 추정 구간, 신호 누락·일부 축만 계산한 기록 등은 비교 판정을 보류합니다. 0.6G는 음성 억제와 공유하는 팀의 시제품 정책(D)이며 물리적 상한·입력 오류 검출·사고 판정 기준이 아닙니다. 같은 출처의 큰 속도 변화를 임의로 삭제하거나 더 낮은 최대값으로 바꾸지 않습니다. 실차 G 정확도와 적재물 효과는 별도 검증 대상입니다.

**분류별 초기값과 요청.** 근거 등급은 A=공식 자료·직접 측정, B=문헌·지침, C=물리 유도, D=팀 가정입니다. 아래 G는 파손·넘침의 확정 한계가 아니라 코칭 초기값이며, 포장·고정·시트 조건별 검증이 필요합니다.

| 보호 분류 | 기본 한계 | 현재 프리셋 요청 | 근거·적용 경계 |
|---|---|---|---|
| 케이크·디저트 / 신선식품 | 0.15G | 케이크 조수석 18℃·열선/통풍 OFF, 지원 시 풍량·풍향. 신선식품은 독립 후석 존 18℃ 요청 | C+D: 마찰계수 0.3 가정의 절반. 18℃는 설정값이며 상자 내부 온도·냉장 보관을 뜻하지 않음 |
| 뜨거운 음식 / 음료·국물 | 0.12G | 뜨거운 음식은 통풍 OFF·독립 존 송풍 OFF 요청. 음료·국물은 공조 변경 없음 | C+B+D: 용기 여유 높이·폭 기반 초기값. 열선 2단은 분류 정의에만 있고 ON은 기존 동의와 무관하게 차단 |
| 꽃·식물 / 반려동물 / 일반 짐 | 0.20G | 꽃은 22℃·간접풍·열선 OFF, 반려동물은 22℃·간접풍·열선/통풍 OFF 요청. 일반 짐은 공조 변경 없음 | B+D: 사람의 불편 연구를 참고한 값으로 꽃 수명·동물 건강을 입증하지 않음. 대표 효능 검증 범위에서 제외 |
| 깨지기 쉬운 물건 | 0.12G | 공조 변경 없음 | C+D: 단순 전도 모델 기반. 파손 강도·완충재 성능 측정값이 아님 |
| 전자기기·악기 | 0.25G | 열선 OFF 요청 | C+D: 포장된 강체 가정. 종류별 충격 내성으로 일반화하지 않음 |

**실패 시 행동.** 주행 또는 AAOS UX 제한에서는 목록·설정 조작을 숨기며 실행 직전 정차 조건을 재검사합니다. 차속 수신 후 2초가 지나면 추정을 멈추고 조향만 만료되면 가감속만 추정합니다(D). 공조·시트를 요청한 세션에서 빈 좌석 확인을 잃으면 종료하고 정차·현재 값 확인을 거쳐 조건부 복원을 요청합니다. 설정 변경이 없는 G 세션은 유지합니다. 실행 중 복원 실패는 새 적용을 보류하고 P 정차 후 재확인 경로를 제공합니다. 원래 값을 모르면 임의 기본값으로 복원하지 않습니다.

**기록과 개인정보.** 앱 자체 서버·외부 분석 수집 모듈은 없습니다. 최근 VIP 이름·분류와 설정은 차량 로컬에 저장·삭제하며 리포트는 현재 세션 화면에서 봅니다. 인식 텍스트는 UI·진단 로그에 나타날 수 있습니다. Pleos 음성·위치 서비스의 데이터 처리는 플랫폼 정책 범위이며, 향후 연구 기록은 별도 동의·최소 수집·보관 기간을 정해 진행합니다.

## 4. 주요 사용 시나리오

**A — 케이크를 먼저 싣고 귀가하는 기본 흐름.**
1. 케이크 상자를 조수석 시트 위에 안정적으로 놓은 뒤, 운전자가 P단·정차 상태에서 앱을 엽니다. 현재 자리가 조수석이면 최근·추천의 케이크를 1탭 선택합니다. 다른 자리일 때만 자리 변경 1탭을 더합니다.
2. 0.15G 코칭 세션이 시작됩니다. 확인된 AVD의 빈 좌석에서는 조수석 18℃·열선 OFF 등의 설정 결과를 표시합니다. 공유 풍량·풍향은 유지합니다. 실차·미확인 조합에서는 설정을 보류하고 유효 신호로 가능한 코칭·챙김을 사용합니다. ‘설정값 확인’은 냉방 작동이나 상자 내부 온도 확인과 다릅니다.
3. 출발하면 정적 배지를 표시하고 정책이 허용한 효과음·짧은 코칭을 제공합니다. 운전자는 교통 상황을 우선합니다. 실제 케이크 상태를 감지하거나 파손 여부를 판정하지 않습니다.
4. 내비 도착 뒤 P단·정차 또는 P단·정차 중 운전석 문 열림에 챙김과 복원을 요청합니다. 설정값 복원이 확인되면 짧은 완료 표시로 끝내고 케이크를 챙깁니다. 실패·미확인 항목이 있을 때만 해당 항목의 수동 확인을 안내합니다.

**B — 퇴근길 포장음식과 음료를 반복 운반.** 이 시나리오의 포장음식은 **‘뜨거운 음식’ 분류(HOT_FOOD)**입니다. 0.12G 코칭·챙김과 함께 지원되는 좌석 통풍 OFF·독립 존 송풍 OFF를 요청하되, 열선 ON은 차단하고 공유 송풍은 유지합니다. 실제 요청·유지·보류 결과는 항목별로 표시하며 보온 효과를 약속하지 않습니다. 별도의 ‘음료·국물’ 분류(COFFEE)는 0.12G 코칭·챙김을 제공하고 차량 설정을 바꾸지 않습니다. 두 분류와 제어 지원 여부를 나누어, 다음 운반 기회에 스스로 다시 켜는지 관찰합니다. 코칭이 불편하면 정차 후 음성을 끄거나 종료할 수 있습니다.

**C — 중간 정차·미지원·입력 실패.**
