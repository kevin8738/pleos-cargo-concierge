앱명 / 프로젝트명: **VIP 조수석 (Cargo Concierge)**

## 1. 앱 한 줄 소개
이미 실은 소중한 짐을 정차 홈에서 한 번 선택하면, 품목별 주행 코칭·도착 챙김과 지원되는 차량 설정·복원을 이어 주는 Pleos 차량용 앱입니다.

## 2. 기획 배경

**고객 순간:** 조수석에 케이크나 퇴근길 포장음식을 실은 Pleos 운전자가 출발을 준비합니다.
**불편:** 설정 확인, 쏠림 주의, 도착 후 챙김과 설정 복원을 각각 기억해야 합니다.
**차량 전용 흐름:** 선적재 → 정차 중 앱 열기 → 현재 자리의 최근·추천 VIP 1탭 → 설정 결과·코칭 → 도착 챙김·조건부 복원으로 연결합니다.
**현재 증거:** 제출 APK 공식 AVD에서 제어·과거 설정 조회·전체 동선을 확인했습니다. 별도 관측 APK의 합성 계산·에뮬레이터 음향 관측과 실패는 보존하며 실제 운전자·실차 G·물건 효과·재사용·구매 결과는 0건입니다.

가족 운전자를 우선 탐색하고 케이크를 첫 경험, 뜨거운 포장음식을 반복 장면으로 봅니다. 포장음식 주 1~2회는 팀 가정(D)입니다. 다른 자리면 선택 1탭을 더하며, 조작 수는 UI 경로이지 사용자 성과가 아닙니다. 운전자가 물건 고정·운전과 앱 시작을 맡습니다. 앱 실행 전 도어 이력·백그라운드 자동 호출은 미연동이며, 도어 제안은 앱이 신호를 받는 동안만 제공합니다.

| 제공 범위 | 운전자가 받는 경험 | 확인 수준 |
|---|---|---|
| 설정 변경 없는 기본 경험 | 선택한 짐의 한계로 코칭하고 내비·P단·도어를 종료 판단에 연결해 챙김 안내 | 구현·AVD 관측. 실차는 유효 신호·권한 확인 필요 |
| 확인된 AVD의 설정 | P단·정차·빈 좌석·원값·지원 항목 확인 후 요청. 온도는 SYNC OFF도 확인하고 종료 때 조건부 복원 | 설정값 왕복 확인. 상자 온도·냉방 효과 미측정 |
| 실차·미확인 조합 | 공조·시트 요청 보류와 항목별 이유 표시, 가능한 코칭·챙김 유지 | 적재별 점유·권한·제어·물리 성능 검증 전 |

검증할 가치는 **시작한 뒤 평소보다 설정·코칭·종료 확인이 편리한가**입니다. 수동 설정·개별 음성 제어에는 품목·자리별 요청/복원 상태를 더하고, 스마트폰 가속도 앱·주행 기록·순정 내비와는 차량 신호를 짐 세션에 연결하는 흐름을 비교합니다. 하차·후석 알림은 제공 차종에서 비교하며 보냉백·완충재·적재 고정은 계속 사용합니다. 별도 적재물 센서·서버 없이 차량 신호·설정·내비·화면·스피커를 잇는 구현이며 스마트폰 대비 정확도·부담·우월성·독점성은 미입증입니다.

제조사·플랫폼 서비스 상품 조직의 도입이 주 지불 가설(D)이며 구매·계약·채널 결과는 없습니다. 과업 시간·놓친 항목·상태 오해와 **기회별 자발 시작·완료**를 설정 지원별로 비교할 계획입니다(§6). 수치는 A=공식/직접 관측, B=문헌, C=계산, D=팀 가정으로 표시합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

대표 검증은 **케이크·음료/국물·포장음식·일반 짐**입니다. 구현 9분류를 유지하되 꽃·반려동물·전자기기 등의 효능으로 확대하지 않습니다.

| # | 기능 | 사용자 행동과 앱 반응 | 차량 연동과 현재 경계 |
|---|---|---|---|
| F1 | **정차 빠른 시작·조건부 제안** | 선적재 후 현재 자리의 최근·추천 VIP 1탭, 다른 자리는 1탭 추가. 도어 신호 수신 중 P단·정차에서 문 열림→닫힘이 오면 해당 자리 선택을 10초간 제안 | 착좌 확정·최근 30초 이내 빈 좌석 확인 상실 등은 억제. 같은 트리거 3회 시간 초과 후 일시 억제하고 수동 선택으로 재기회. 출발 시 닫힘. 실행 전 이력·자동 호출 미연동 |
| F2 | **품목·자리별 설정과 상태** | 조수석·후석 좌/중/우·트렁크 선택. 항목별 설정 확인·유지·미지원·보류·실패 표시 | 확인된 AVD에서만 빈 좌석 인정. 실차·미확인 설정 보류. SYNC ON/미확인 시 온도 보류, 운전석 포함 공유 풍량·풍향 유지. 트렁크는 코칭·챙김만, 열선 ON 차단 |
| F3 | **품목별 관성 코칭** | 차속·조향으로 횡G, 차속 변화로 종G 추정. 한계 80% 진입 효과음·초과 코칭, 주행 화면은 정적 배지 우선 | 세션 주행 요청 합계 최대 6회·음성 최대 3회·공통 간격 8초(D). 15 km/h 미만 조향 중심 움직임·0.6G 이상 추정 구간은 관성 코칭 억제. 실차 정확도·청취 부담 미검증 |
| F4 | **경로·도착 연계** | 내비 도착이 먼저면 D단에서 챙김 예고 후 P단·정차 대기. 경유지는 세션 유지 | 경로 상태·TBT 연결. TBT/주의 구역 남은 거리 단위는 공식 문서상 m. 실제 목록 순서·경로 진행·도착·선행 코칭은 추가 검증. 제한속도 이벤트는 판단에 미사용 |
| F5 | **챙김·복원·새 이동** | 내비 도착 후 P단·정차 또는 P단·정차 중 운전석 문 열림에 챙김·복원·리포트. 확인된 종료만 짧게 완료, 실패·미확인만 수동 확인 | 원값 있는 항목만 조건부 복원, 관찰된 외부 변경 유지. 최대 추정 G·평균 설정 온도·시간·요청 수 표시. 같은 VIP 재시작은 새 세션. 비정상 종료 후 수동 확인 안내와 남은 과거 설정 조회. 자동 복원 없음 |
| F6 | **말로 등록·최근 VIP** | 정차 중 이름·자리 파싱, 모르는 이름은 일반 짐으로 시작. 분류 변경·최근 VIP 로컬 저장/삭제 | 앱 내 STT·별칭 사전 구현, 인식 실패 시 화면 선택. Gleo 호출어·외부 음성 진입은 향후이며 LLM으로 물건 상태를 판단하지 않음 |

**알림과 세션의 단위.** 6회·3회·8초는 앱 주행 **요청** 정책이며 재생 완료·차량 전체 소리의 상한이 아닙니다. 같은 VIP 재시작도 통계·예산을 새로 시작합니다. 30분 관찰창의 세션/재시작 수·누적 요청·실제 소리·내비 중첩은 따로 기록하며 ‘30분당 최대 6회’를 보장하지 않습니다.

사용자가 정차 중 시작한 세션은 실행 알림과 함께 다른 화면에서도 이어집니다. 서비스 시작 실패 시 가드·차량 요청을 시작하지 않고 이유를 표시하며, 정상 종료는 진행 중 차량 처리를 마친 뒤 서비스를 중지합니다(근거 §5).

**리포트의 판정 범위.** 공식 AVD·Mock 입력을 알면 ‘모의 입력·실주행 평가 불가’를 표시하고 최대값을 보존합니다. 0.6G 이상·신호 누락·일부 축만 계산한 기록은 비교를 보류합니다. 0.6G는 음성 억제와 공유하는 시제품 정책(D)으로 물리 상한·입력 오류 검출·사고 기준이 아닙니다. 같은 출처의 큰 속도 변화를 삭제하거나 최대값을 낮추지 않으며 실차 정확도·짐 효과는 별도 검증합니다.

**분류별 초기값.** G는 코칭 초기값이며 파손·넘침 한계가 아닙니다. 포장·고정·시트별 검증이 필요합니다.

| 보호 분류 | 기본 한계 | 현재 프리셋 요청 | 근거·적용 경계 |
|---|---|---|---|
| 케이크·디저트 / 신선식품 | 0.15G | 케이크 조수석 18℃·열선/통풍 OFF, 지원 시 풍량·풍향. 신선식품 독립 후석 존 18℃ | C+D: 마찰계수 0.3 가정의 절반. 18℃는 설정값, 상자 온도·냉장 보관 아님 |
| 뜨거운 음식 / 음료·국물 | 0.12G | 뜨거운 음식 통풍 OFF·독립 존 송풍 OFF. 음료·국물 공조 변경 없음 | C+B+D: 용기 여유 높이·폭 기반. 열선 2단은 정의에만 있고 기존 동의와 무관하게 ON 차단 |
| 꽃·식물 / 반려동물 / 일반 짐 | 0.20G | 꽃 22℃·간접풍·열선 OFF, 반려동물 22℃·간접풍·열선/통풍 OFF. 일반 짐 변경 없음 | B+D: 사람 불편 연구 참고. 꽃 수명·동물 건강 미입증, 대표 효능 검증 제외 |
| 깨지기 쉬운 물건 | 0.12G | 공조 변경 없음 | C+D: 단순 전도 모델, 파손 강도·완충재 측정값 아님 |
| 전자기기·악기 | 0.25G | 열선 OFF | C+D: 포장 강체 가정, 종류별 충격 내성으로 일반화하지 않음 |

**실패 시 행동.** 주행·AAOS UX 제한에서는 목록/설정을 숨기고 실행 직전 정차를 재검사합니다. 차속 수신 후 2초가 지나면 추정을 멈추며 조향만 만료되면 가감속만 추정합니다(D). 설정 요청 세션이 빈 좌석 확인을 잃으면 종료 후 정차·현재 값 확인을 거쳐 조건부 복원합니다. 설정 없는 G 세션은 유지합니다. 복원 실패는 새 적용을 보류하고 P 정차 재확인을 제공하며, 원값을 모르면 임의 기본값으로 복원하지 않습니다.

**과거 설정 조회.** 남아 있는 당시 변경 전 조회값·적용/복원 요청 직전 값·마지막 독립 확인값을 시각·실제 제어 출처·영역과 함께 보여 줍니다. 요청 직전 기록만으로 실행·수락을 확정하지 않습니다. 현재 값·권장 복원값이 아니며, 조회로 차량 요청·복원 권한·서비스를 되살리지 않습니다. 최신 P·정차 확인과 UX 제한 해제 때만 열리고 제한 전환 시 닫힙니다. 남아 있는 미완료 기록 1건과 이번 실행 1건을 로컬에 보관하며 누락·손상·미확인은 그대로 표시합니다. 모든 중단에서 기록 보존을 보장하지 않으며 기존 수동 확인 안내를 유지합니다.

**기록·개인정보.** 앱 자체 서버·외부 분석 수집 모듈은 없습니다. 최근 VIP 이름·분류·설정은 차량 로컬 저장/삭제, 리포트는 현재 세션 화면에서 봅니다. 인식 텍스트는 UI·진단 로그에 나타날 수 있습니다. Pleos 음성·위치 처리는 플랫폼 정책을 따르며 연구 기록은 별도 동의·최소 수집·보관 기간을 정합니다.

## 4. 주요 사용 시나리오

**A — 케이크를 먼저 싣고 귀가.** 운전자가 상자를 조수석에 안정적으로 놓고 P단·정차에서 앱을 엽니다. 현재 자리의 케이크 1탭, 다른 자리는 자리 선택 1탭을 더합니다.

| 상황 | 기본 경험 | 지원되는 설정·확인 |
|---|---|---|
| 출발 준비 | 0.15G 코칭 세션 시작 | 확인된 AVD 빈 좌석에서 18℃·열선 OFF 등 결과 표시. 공유 풍량·풍향 유지. 실차·미확인 설정 보류 |
| 주행 | 정적 배지·정책이 허용한 효과음/코칭. 운전자는 교통 우선 | 설정값 확인은 냉방·상자 온도 측정이 아니며 케이크 상태·파손을 감지하지 않음 |
| 도착 | 내비 도착 후 P 정차 또는 P 정차 중 운전석 문 열림에 챙김·복원 | 복원 확인 시 짧은 완료, 실패·미확인 항목만 수동 확인 |

**B — 퇴근길 포장음식·음료의 반복 운반.** 다음 운반 기회에 자발적으로 다시 켜는지 분류·제어 지원별로 관찰합니다. 불편하면 정차 후 음성을 끄거나 종료합니다.

| 구분 | 기본 경험 | 차량 설정 |
|---|---|---|
| 뜨거운 음식(HOT_FOOD) | 0.12G 코칭·챙김 | 지원 시 통풍 OFF·독립 존 송풍 OFF, 공유 송풍 유지·열선 ON 차단. 항목별 결과 표시, 보온 효과 약속 없음 |
| 음료·국물(COFFEE) | 0.12G 코칭·챙김 | 변경 없음 |

**C — 중간 정차·미지원·실패.**

| 상황 | 현재 처리 | 사용자가 확인할 것 |
|---|---|---|

**제어 확대 조건.** Vehicle SDK 2.3.2·Service 2.3.22(code 74)·crp_avd_arm64·API 34가 모두 맞는 AVD에서만 빈 좌석 응답을 인정합니다. 실차·미확인 설정은 보류합니다. 원시 점유 1(빈 좌석)은 true, 0(미확인)·2(착좌)는 false로 합쳐져 false를 반전하지 않습니다. **짐 하중 때문에 사람이 없어도 빈 좌석 응답이 없을 수 있습니다.** 승인 차량에서 질량·바닥 면적·배치별 응답·권한·독립 존·공조 작동·복원 경합을 확인하며 사용자 확인으로 보류를 우회하지 않습니다. 설정값 평균과 상자 온도도 별도 측정합니다.

**구현 구조.** Kotlin·Jetpack Compose 단일 Activity, 차량/내비/음성 포트와 `CargoSession`이 상태·수신·주기를 담당하고 전경 서비스가 실행을 유지합니다. 차량 제어는 순차 처리, 오래된 요청·이전 세션의 늦은 결과는 차단합니다. 차속 신선도 2초·지연 설정 재조회 최대 1초/100ms 간격은 D 정책이며 데모 브리지는 DUMP 권한 shell 시험용입니다. Gleo·실행 전 자동 노출·지오펜스·영구 리포트 공유·마켓 적합성은 후속 범위입니다.
