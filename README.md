# VIP 조수석 Cargo Concierge

케이크·포장음식 등 차량에 실은 짐을 선택하면 지원되는 차량 설정·주행 코칭·도착 챙김을 이어 주는 **Pleos Connect 차량용 앱**입니다. 팀명은 **VIPSeat**입니다.

v24 공개본 A4 14쪽·대표자 서명본 A4 14쪽의 구조 감사와 전 페이지 시각 검수를 확인했습니다. v23·v22 공개본·서명본 각 A4 15쪽과 당시 검수·패키지는 이전 제출 이력으로 보존합니다. [v1.1.3 검증·영상](docs/검증자료/AVD_v1.1.3/README.md)과 v21 접수양식도 이전 제출 이력입니다. 앱 v1.1.4/code 7, 기존 182개 시험·A1–A5 화면·82.287311초 영상과 시뮬레이션 v2.3은 유지합니다.

v24는 제공 범위·PT 절차·현장 판정 규칙을 정리하고 같은 APK의 통합 관측과 실제 코어 계산을 추가했습니다. 통합 관측은 조향 기록 1행 공백·시계 보정 불일치·도착 음향 대비 미충족으로 전체 false를 유지합니다. 54계산에서 반복 입력은 약 101초에 전체 6회 요청을 사용했고 입력 주기에 따라 음성/효과음 구성이 달랐습니다. 실제 음향 경합·실차 정확도·짐 효과·사용자 가치·구매 결과의 검증과 구분합니다.

v1.0.0 당시 시연·컨셉 영상은 [Release v1.0.0](https://github.com/kevin8738/pleos-cargo-concierge/releases/tag/v1.0.0)에 있습니다. 시연 영상의 기존 다운로드 파일명은 링크 호환을 위해 유지했습니다. [v1.1.1 온도 왕복 무음 영상 30.0초](docs/검증자료/AVD_v1.1.1/온도왕복_무음.mp4)는 이전 버전의 기록입니다. 저장소의 `apk/`에는 제출 대상 Pleos release APK 한 개를 둡니다.

## APK 실행

공식 **Pleos_Connect_v2.1** 에뮬레이터를 부팅한 뒤 저장소 루트에서 실행합니다. v1.1.4의 AVD 비착좌 확인 경로는 Vehicle SDK **2.3.2**, VehicleService **2.3.22(versionCode 74)**, **crp_avd_arm64 / API 34** 조합으로 한정합니다. 다른 버전·환경에 같은 해석을 적용하지 않습니다.

```bash
adb install -r -g apk/VIPSeat_CargoConcierge_release.apk
adb shell am start -n ai.vipseat.cargoconcierge/.MainActivity
```

설치 후 Android **설정 → 앱 → VIP 조수석 → 권한 → 위치**에서 **앱 사용 중에만 허용**을 선택하고, 앱 알림을 허용합니다. GPS 보조 입력을 사용하려면 시스템 위치도 켭니다. 현재 검증은 실제 설정 UI에서 이 상태를 확인한 결과입니다. `-g` 설치 옵션만으로 위치·알림 설정 확인을 대신하지 않습니다. 위치를 사용하지 않는 상태도 지원하지만 GPS 보조 입력은 중단됩니다.

기존 debug 앱과 서명이 달라 설치가 실패하면 해당 앱을 제거한 뒤 설치해야 합니다. 앱 제거 시 기존 앱 데이터도 지워집니다.

실제 제어를 재현하려면 공식 Emulator Console의 브라우저 화면(`http://127.0.0.1:8088/`)을 열어 heartbeat가 활성인 상태를 유지합니다. P단·정차와 비착좌를 실제 SDK 값으로 확인하고, 온도 변경은 SYNC가 꺼졌다고 확인되는 조건에서 시작합니다. 원래 설정값·상태·SYNC를 확인하지 못하면 변경을 보류합니다. 공조 전원이 꺼진 상태에서도 설정값 조회·변경은 가능하며, 앱은 전원을 켜지 않습니다. 조건별 준비와 실제 요청·관측값은 [AVD 검증 기록](docs/검증자료/AVD_v1.1.4/README.md)을 따릅니다.

앱의 **케이크 시나리오** 버튼과 [PT 대본](demo/PT_SCRIPT.md)은 화면·코칭 재현에 사용할 수 있습니다. 데모로 주입한 기어·속도·착좌 신호는 실제 차량 제어의 허용 근거가 아닙니다. 차량 제어 직전의 조건은 실제 SDK로 다시 확인합니다. 수동 화면 신호를 주입할 때는 기어·속도를 2초 안에 갱신해야 하며, 갱신이 멈추면 신호 확인 상태로 전환됩니다.

## 소스 빌드와 검증

저장소를 복제한 루트에서 실행합니다. 첫 빌드는 Gradle·Android·Pleos 의존성을 받을 네트워크가 필요합니다.

```bash
./gradlew :core:test :app:testPleosDebugUnitTest
./gradlew assemblePleosDebug
```

생성 APK는 `app/build/outputs/apk/pleos/debug/app-pleos-debug.apk`입니다. 표준 AAOS용 개발 빌드는 `./gradlew assembleMockDebug`로 생성할 수 있습니다.

제출 APK의 무결성은 다음 명령으로 확인합니다.

```bash
cd apk
shasum -a 256 -c SHA256SUMS.txt
```

접수용 APK는 release 키로 서명했으며, 키는 배포하지 않습니다. 소스에서 재빌드한 APK는 제출 APK와 서명이 다를 수 있습니다. 제출 APK 정보는 [APK 안내](apk/README.md)를 참고하세요.

현재 v1.1.4-pleos APK는 **47,871,331 bytes**이며 SHA-256은 `8971e207285f333c2c152f185e907ea1d38c01c04369473fc68c8f850f5e023c`입니다.

## 3D 비교 시연

```bash
cd docs/sim
python3 -m http.server 8788 --bind 127.0.0.1
```

[로컬 시뮬레이션](http://127.0.0.1:8788/)에서 **비교 시작**을 누르면 시뮬레이션의 일반 주행 비교 설정과 케이크 기준 주행을 동시에 볼 수 있습니다. 화면의 ‘사람 기준’은 비교용 설정명이며 사람의 안전 한계나 실측값을 뜻하지 않습니다. `1`은 체이스, `2`는 캐빈, `3`은 지도입니다. 첫 로딩에는 Three.js와 글꼴을 받을 네트워크가 필요합니다.

2021 아이오닉 5 공식 사진을 참고한 차체·실내·20인치 휠을 사용합니다. 케이크는 조수석 시트 위에 있으며 화면·핸들·제동등이 주행에 연동됩니다. 시각화 모델의 세부 형상은 사진 기반 근사입니다. 계산 결과와 손상 표현은 실차 시험값이 아니며, 수치의 출처·등급은 [근거표](docs/근거_EVIDENCE.md)에 구분했습니다.

## 검증 범위와 알려진 제한

- **코어 158개·앱 24개, 총 182개 테스트 통과**(실패·오류·건너뜀 0), release 빌드·서명 검사·Mock 컴파일 통과, lint 오류 0·경고 33입니다. 현재 APK의 시험·원자료·수정 전 실패 이력은 [v1.1.4 검증 기록](docs/검증_v1.1.4.md)과 [증거 색인](docs/검증자료/AVD_v1.1.4/README.md)에 연결했습니다.
- 현재 AVD의 제어 10조건과 연속 동선 9항목을 확인했습니다. 정상 22→18→22℃ 재조회, 착좌 미확인 보류, 외부 변경 보존, 비착좌 확인 상실, 전원 OFF, SYNC 및 주행 상태에 따른 복원 보류·명시적 재시도, 재시작 시 미확인 안내를 포함합니다. 공조 설정값 확인이며 실내·짐 온도나 냉방 효과의 계측은 아닙니다. 적용 후 전원 표시는 당시 조회이고 복원 후 전원 확인은 포함하지 않습니다.
- 사용자가 시작한 보호 세션은 알림이 있는 포그라운드 서비스로 유지됩니다. 순정 내비 화면으로 전환한 직접 관측 구간 20.297990초에서 보수적으로 20개 주기 실행(최대 간격 1,007ms)과 TBT 6개를 확인했습니다. 서비스 시작 차단·복구, 강제 종료·셸 태스크 제거 후 자동 재시작 없음도 확인했습니다. 위치 ON/OFF 검사는 구독·서비스 유형 경계 관측이며 GPS 위치·속도 정확도 검증은 아닙니다.
- 정상범위·경고경계 시험은 일정한 5m/s와 조향 합성 입력으로 독립 계산·배지·경고 요청·도착 리포트를 대조했습니다. 약 0.0924G 정상, 0.1027G 경고, 0.1235G 초과와 회복을 확인했습니다. 음향 OFF 시험의 요청 건수는 실제 재생 횟수가 아닙니다. 품목별 한계와 음성·효과음 공통 8초 간격, 세션당 합계 6회·음성 최대 3회는 검증 전 시제품 정책(D)입니다.
- 기존 COFFEE 선택 음향 시험의 TTS·차임 수신 PCM 및 OFF 대조는 보존합니다. 같은 APK의 추가 합성 주행에서 WARN 허용 1회 창의 PCM peak는 152(OFF 2), OVER 허용 2회 창은 1,345(OFF 2)였습니다. 각 주행 TTS의 START→DONE을 확인했고 ERROR는 0회였습니다. 같은 trip의 합성 도착 보고서까지 연결했으며 도착 발화는 수집하지 않았습니다. ON 원 실행의 cleanup 실패는 그대로 보존하고 별도 복구 기록을 연결했습니다. OFF 실행은 정상 정리됐습니다. native-only 캡처에서는 출력 peak를 관측했지만 경로 활성 구간 전체를 수집하지 못해 음향 내용과 앱 코칭의 경합은 미확인입니다. 희소 PCM의 길이는 연속 wall time이 아니며 청취 명료도·차량 스피커·운전자 부담은 미검증입니다.
- 기존 전체 동선 영상은 **82.287311초·2560×1440·34,623,201 bytes, 오디오 스트림 0개**입니다. 최대 **4.49G** 원값과 ‘모의 입력·실주행 평가 불가·고G 원인 미확인’을 보존합니다. 별도 flow trace의 최대값은 4.4372528175G이며, accepted speed 34→1km/h·수신 간격 0.101초와 EMA 계산이 일치했습니다. 이는 새 관측이며 이전 4.49G의 정확한 입력 쌍·원인을 소급 확정하지 않습니다. 실차 G 정확도나 물건 보호 효과의 검증도 아닙니다. 0.6G 판정 유보는 검증 전 팀 정책(D)이며 과거 3.69G·4.53G와 정확도 개선으로 비교하지 않습니다.
- 앱은 원값을 읽은 항목만 변경하고 현재값 대조·요청 후 읽기로 조건부 복원합니다. 읽기/쓰기 사이 외부 변경 경쟁과 프로세스 종료 후 자동 복원은 지원 범위 밖입니다. 보온 열선 ON은 검증 대기로 차단하며 30/45분을 안전 타이머로 구현하지 않았습니다.
- 시뮬레이션 v2.3의 전체 코스 검사 36개와 기존 A/B 계산 결과는 유지합니다. 실차·물건 보호 효과의 실측과 구분합니다. 실제 참가자 과업·G·온도 계측·재사용·구매·채널 결과는 0건이며 현장 CSV 8종은 모두 데이터 0행입니다.
- 컨셉 영상은 생성형 AI 연출과 에뮬레이터 화면 합성입니다. 기존 v1.0.0 시연의 후처리 합성 음성은 현재 음향 검증으로 사용하지 않습니다. Gleo 호출어·외부 연동은 확장 계획이며 현재 음성 입력은 앱 내 말하기 버튼과 Pleos/Android STT·텍스트 파서를 사용합니다.
